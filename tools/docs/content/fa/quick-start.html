در این صفحه چه می‌کنید

در این صفحه بسته را نصب می‌کنید، اولین تاریخ جلالی را چاپ می‌کنید، اولین اعتبارسنجی را اجرا می‌کنید و اولین استثنای کتابخانه را می‌گیرید. همه‌چیز روی PHP ساده اجرا می‌شود؛ نه فریم‌ورک لازم است، نه فایل پیکربندی و نه وابستگی اضافه.

پیش‌نیاز. PHP نسخهٔ 8.2 یا بالاتر با افزونهٔ استاندارد mbstring و کامپوزر. اگر نه PHP دارید نه کامپوزر، مسیر داکر را در نصب ببینید.

۱. نصب

composer require enaxon/rtly-kit

کامپوزر بسته را نصب و فایل vendor/autoload.php را تولید می‌کند. RTLY-Kit هیچ وابستگی الزامی کامپوزری ندارد. یکپارچگی‌های اختیاری (ماکروهای Carbon، لاراول) خودشان با حضور Carbon یا لاراول فعال می‌شوند. جزئیات در نصب.

۲. اولین تاریخ

فایل quick.php را کنار پوشهٔ vendor/ بسازید:

<?php
declare(strict_types=1);

require __DIR__.'/vendor/autoload.php';

use function RtlyKit\hdate;
use function RtlyKit\jdate;

echo jdate('2026-03-21')->format('l j F Y'), "\n";   // شنبه 1 فروردین 1405
echo hdate('2026-03-21')->format('j F Y', 'en'), "\n"; // 2 Shawwal 1447

با php quick.php اجرا کنید. خط اول تاریخ جلالیِ 21 مارس 2026 را چاپ می‌کند که نوروز 1405 است. خط دوم همان روز را در تقویم هجری نشان می‌دهد.

دو نکته:

  • توابع کمکی در فضای‌نام RtlyKit هستند و با use function وارد می‌شوند؛ پس هرگز با تابع شما یا بستهٔ دیگر تداخل نمی‌کنند.
  • رشتهٔ '2026-03-21' میلادی خوانده می‌شود. رشته‌ای مثل '1405/01/01' (سال کمتر از 1700 به شکل Y/m/d) جلالی خوانده می‌شود. معنای رشته در make() را ببینید.
echo jdate('1405/01/01')->toGregorian()->format('Y-m-d'), "\n";   // 2026-03-21

تابع کمکی یک شیء Jalali برمی‌گرداند (و hdate() یک Hijri و hebrew_date() یک Hebrew). این اشیاء تغییرناپذیرند: addDays()، startOfMonth() و دیگر متدهای تغییردهنده شیء تازه برمی‌گردانند.

۳. اختیاری: نام‌های کوتاه سراسری

به‌طور پیش‌فرض هیچ تابع سراسری تعریف نمی‌شود. اگر jdate() و is_national_code() ساده را ترجیح می‌دهید، یک بار، مثلاً در فایل راه‌اندازی، فعالشان کنید:

$skipped = \RtlyKit\Globals::register();   // آرایهٔ نام‌هایی که نتوانست تعریف کند

echo jdate('2026-03-21')->format('Y/m/d'), "\n";   // 1405/01/01

register() از 27 نام کمکی، آن‌هایی را که آزادند تعریف می‌کند. هرگز تابع موجود را بازنویسی نمی‌کند و هرگز پرتاب نمی‌کند؛ فهرست نام‌های ردشده را برمی‌گرداند (آرایهٔ خالی یعنی همه تعریف شدند) و فراخوانی چندباره‌اش بی‌خطر است. برای هر نام ردشده از شکل فضای‌نام‌دار استفاده کنید. جزئیات: توابع کمکی و سراسری‌ها.

۴. اولین اعتبارسنجی

use function RtlyKit\is_national_code;
use function RtlyKit\validate_national_code;
use function RtlyKit\to_persian_digits;
use function RtlyKit\number_to_words;

var_dump(is_national_code('0013542419'));       // bool(true)

$result = validate_national_code('0013542410');
var_dump($result->isValid());                  // bool(false)
print_r($result->errors());                    // [0] => invalid_checksum

echo to_persian_digits('1405/01/01'), "\n";    // ۱۴۰۵/۰۱/۰۱
echo number_to_words(1405), "\n";              // یک هزار و چهارصد و پنج

توابع is_*() یک bool ساده برمی‌گردانند. توابع validate_*() یک Result با isValid()، کلیدهای پایدار و ماشین‌خوان errors() و details() می‌دهند. اعتبارسنج‌ها برای ورودی بد کاربر پرتاب نمی‌کنند؛ گزارش می‌دهند. نمای کلی اعتبارسنج‌ها و کد ملی را ببینید.

۵. اولین استثنا

کد تقویم با اعتبارسنجی فرق دارد: ساختن تاریخ ناممکن خطای برنامه‌نویسی یا دادهٔ نادرست است، پس کلاس‌های تقویم پرتاب می‌کنند. 1404 کبیسه نیست، بنابراین ۳۰ اسفند 1404 وجود ندارد:

use RtlyKit\Exceptions\InvalidDateException;
use RtlyKit\Exceptions\RtlyKitThrowable;

try {
    jdate('1404/12/30');
} catch (InvalidDateException $e) {
    echo get_class($e), ': ', $e->getMessage(), ' [', $e->getErrorCode()->value, "]\n";
}
// RtlyKit\Exceptions\InvalidDateException: Invalid Jalali date: 1404/12/30 [invalid_date]

try {
    jdate('not a date');
} catch (RtlyKitThrowable $e) {
    echo 'library error: ', $e->getMessage(), "\n";   // library error: Unable to parse date: not a date
}

همهٔ استثناهای کتابخانه RtlyKit\Exceptions\RtlyKitThrowable را پیاده می‌کنند و از \InvalidArgumentException ارث می‌برند؛ پس یک catch همه را می‌گیرد و getErrorCode() مقدار پایداری برای شاخه‌بندی می‌دهد (متن پیام را پارس نکنید). ورودی بیرون از بازه، از جمله سال بیرون از بازه‌های پشتیبانی‌شده (جلالی -620 تا 9377، هجری 1 تا 9665، عبری 3762 تا 13759)، همیشه InvalidDateException پرتاب می‌کند، نه TypeError. بیشتر در مدیریت خطا.

چیزهایی که زود باید بدانید

محدودیت شناخته‌شده. تقویم جلالی اینجا قاعدهٔ حسابی ۳۳ ساله است، نه تقویم نجومی رسمی. جدول ام‌القری هجری (1300 تا 1500 هجری قمری) از دادهٔ ICU/CLDR آمده و ماه‌به‌ماه با انتشار رسمی راستی‌آزمایی نشده است. پیش از استفاده برای مهلت‌های قانونی یا مناسکی، دقت و داده‌ها را بخوانید.
  • منطقهٔ زمانی. بدون DateTimeZone صریح، منطقهٔ پیش‌فرض PHP به کار می‌رود. هر وقت روز تقویمی مهم است منطقه بدهید (مثلاً new DateTimeZone('Asia/Tehran')).
  • روز هفته. جلالی از شنبه = 0 شماره‌گذاری می‌کند؛ هجری و عبری از یکشنبه = 0.
