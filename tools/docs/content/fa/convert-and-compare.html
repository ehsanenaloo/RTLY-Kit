یک لحظه، سه تقویم

سه کلاس تقویم (جلالی، هجری، عبری) یک طراحی مشترک دارند: هر کدام فقط یک لحظهٔ DateTimeImmutable را در خود نگه می‌دارد و آن را در تقویم خودش نمایش می‌دهد. پس تبدیل بین تقویم‌ها هرگز از متن عبور نمی‌کند؛ همان لحظه است که با قواعد دیگری خوانده می‌شود. دو نتیجه:

  • تبدیل یک تاریخ و بازگرداندن آن همان لحظه را برمی‌گرداند.
  • مقایسه یا تفریق تاریخ‌های تقویم‌های مختلف همیشه معنا دارد، چون به‌صورت لحظه مقایسه می‌شوند.

همهٔ مثال‌ها این ابتدای فایل را دارند:

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Hebrew;
use RtlyKit\Calendar\Hijri;
use RtlyKit\Calendar\Jalali;
use RtlyKit\Contracts\CalendarDate;
use RtlyKit\Exceptions\InvalidDateException;

$utc = new DateTimeZone('UTC');

تبدیل بین تقویم‌ها

تاریخ را به make() کلاس دیگر بدهید

هر make() یک CalendarDate را می‌پذیرد (و همچنین DateTimeInterface، زمان یونیکس، رشته یا null). تاریخی را که دارید به کلاسی که می‌خواهید بدهید:

$j = Jalali::create(1405, 1, 1, 12, 0, 0, $utc);

echo Hijri::make($j)->format('Y/m/d F', 'en');    // 1447/10/02 Shawwal
echo Hebrew::make($j)->format('Y/m/d F');          // 5786/07/03 Nisan
echo Jalali::make(Hijri::make($j));                 // 1405/01/01 12:00:00

ساعت و منطقهٔ زمانی منتقل می‌شوند. برای بیان نتیجه در منطقهٔ دیگر، DateTimeZone را آرگومان دوم make() بدهید:

$tehran = new DateTimeZone('Asia/Tehran');

$h = Hijri::make($j, $tehran);
echo $h->getTimezone()->getName();      // Asia/Tehran
echo $h->getHour(), ':', $h->getMinute();   // 15:30   (ساعت 12:00 UTC)
میان‌بر هم‌کلاس. Hijri::make($hijri) و Hebrew::make($hebrew) همان نمونه‌ای را که داده‌اید برمی‌گردانند (آرگومان منطقهٔ زمانی یا گونه نادیده گرفته می‌شود). Jalali::make($jalali) هم همان را برمی‌گرداند، مگر منطقهٔ زمانی بدهید که آنگاه نسخه‌ای در آن منطقه می‌گیرید. برای عوض کردن گونهٔ یک تاریخ هجری از لحظه عبور کنید: Hijri::make($h->toGregorian(), null, HijriVariant::Tabular).

از و به میلادی

toGregorian() همان DateTimeImmutable زیرین را می‌دهد و دادن DateTimeInterface به make() مسیر برعکس است. مبدل‌های استاتیک روی عددهای ساده کار می‌کنند:

$g = new DateTimeImmutable('2026-03-21 12:00', $utc);

echo json_encode([
    Jalali::gregorianToJalali(2026, 3, 21),
    Hijri::gregorianToHijri(2026, 3, 21),
    Hebrew::gregorianToHebrew(2026, 3, 21),
]);
// [[1405,1,1],[1447,10,2],[5786,7,3]]

echo json_encode(Jalali::jalaliToGregorian(1405, 1, 1));   // [2026,3,21]
echo get_class($j->toGregorian());                         // DateTimeImmutable

سال میلادی باید 1 تا 9999 باشد. بازهٔ هر تقویم (جلالی -620 تا 9377، هجری 1 تا 9665، عبری 3762 تا 13759) بخشی از این بازه است که آن تقویم می‌تواند نمایش دهد؛ پس تبدیل یک تاریخ میلادیِ قدیمی به عبری یا هجری ممکن است InvalidDateException بدهد، حتی اگر خودِ تاریخ میلادی معتبر باشد:

try { Hebrew::make(new DateTimeImmutable('0001-01-01', $utc)); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Date out of the supported Hebrew range (3762..13759): 3761

منطقهٔ زمانی تاریخ را تعیین می‌کند

تاریخ تقویمی یک لحظه به منطقه‌ای که در آن نگاهش می‌کنید بستگی دارد. همین لحظه در UTC هنوز اول فروردین 1405 (۲۱ مارس) است ولی در تهران، که 3.5 ساعت جلوتر است، دوم فروردین شده است:

$instant = new DateTimeImmutable('2026-03-21 22:30', $utc);

echo Jalali::make($instant);            // 1405/01/01 22:30:00   (UTC)
echo Jalali::make($instant, $tehran);   // 1405/01/02 02:00:00   (تهران، +03:30)

هر جا روز تقویمی مهم است منطقه را صریح بدهید و به پیش‌فرض سرور تکیه نکنید.

قرارداد CalendarDate

RtlyKit\Contracts\CalendarDate اینترفیسی است که Stringable را گسترش می‌دهد و Jalali، Hijri و Hebrew آن را پیاده می‌کنند. برای نوشتن کدی که با هر تقویمی کار کند، همین نوع را تایپ‌هینت کنید:

function describe(CalendarDate $d): string
{
    return sprintf('%s %d/%02d/%02d', (new ReflectionClass($d))->getShortName(),
        $d->getYear(), $d->getMonth(), $d->getDay());
}

foreach ([Jalali::class, Hijri::class, Hebrew::class] as $class) {
    echo describe($class::make($g)), "\n";
}
// Jalali 1405/01/01
// Hijri 1447/10/02
// Hebrew 5786/07/03
گروهاعضا
ساختmake()، now()، today()، create()
محاسبات تقویمی (استاتیک)isValid()، isLeapYear()، daysInYear()، daysInMonth()
گیرنده‌هاgetYear()، getMonth()، getDay()، getHour()، getMinute()، getSecond()، getDayOfWeek()، getTimestamp()، getTimezone()، toGregorian()
قالب‌بندیformat()، toDateString()، toDateTimeString()، __toString()
تغییرadd/sub برای Days، Hours، Minutes، Seconds، Months، Years؛ startOf/endOf برای Day، Month، Year
مقایسهeq، ne، gt، gte، lt، lte، equals، isBefore، isAfter، between، isPast، isFuture، isToday
اختلافdiffInDays()، diffInMonths()، diffInYears()

تضمین‌هایی که برای هر پیاده‌سازی برقرار است:

  • نمونه‌ها final و تغییرناپذیرند؛ متدهای تغییردهنده شیء تازه برمی‌گردانند.
  • هر متدی که تاریخ، زمان یونیکس یا مقدار جابه‌جایی می‌گیرد، برای ورودی بیرون از بازه فقط InvalidDateException پرتاب می‌کند؛ هرگز TypeError یا ValueError.
  • format() در قرارداد فقط با الگو تعریف شده است؛ هر کلاس پارامترهای اختیاری پایانی خودش را اضافه می‌کند ($persianDigits برای جلالی؛ $locale و $digits برای هجری؛ $locale برای عبری). از طریق اینترفیس فقط format($pattern) قابل فراخوانی است.
  • شمارهٔ روز هفته یکسان نیست: جلالی شنبه‌محور و هجری و عبری یکشنبه‌محورند.
$i = new DateTimeImmutable('2025-10-07', $utc);   // سه‌شنبه
echo Jalali::make($i)->getDayOfWeek(), ' ', Hijri::make($i)->getDayOfWeek(), ' ', Hebrew::make($i)->getDayOfWeek();
// 3 2 2   (جلالی: شنبه = 0؛ دو تقویم دیگر: یکشنبه = 0)

مقایسه بین تقویم‌ها

همهٔ متدهای مقایسه CalendarDate|DateTimeInterface می‌گیرند و زمان یونیکس را مقایسه می‌کنند؛ نیازی به تبدیل قبلی نیست:

$nowruz = Jalali::create(1405, 1, 1, 12, 0, 0, $utc);

var_dump($nowruz->eq(Hijri::make($nowruz)));                     // bool(true)
var_dump($nowruz->eq($nowruz->toGregorian()));                   // bool(true)
var_dump($nowruz->gt(Hebrew::create(5785, 1, 1, 0, 0, 0, $utc)));  // bool(true)
var_dump($nowruz->between(Hijri::create(1447, 8, 1, 0, 0, 0, $utc),
                          Hebrew::create(5787, 1, 1, 0, 0, 0, $utc))); // bool(true)

between($a, $b, $equal = true) کران‌ها را به هر ترتیبی می‌پذیرد و، مگر false بدهید، آن‌ها را هم شامل می‌شود. برابری یعنی برابریِ لحظه: Jalali::create(1405, 1, 1) ساخته‌شده در UTC با همان تاریخ مدنی ساخته‌شده در تهران برابر نیست، چون 3.5 ساعت فاصله دارند.

برای مرتب‌سازی فهرست مخلوط، بر پایهٔ getTimestamp() مرتب کنید:

$list = [
    Hebrew::create(5786, 1, 1, 0, 0, 0, $utc),
    Jalali::create(1405, 1, 1, 0, 0, 0, $utc),
    Hijri::create(1447, 1, 1, 0, 0, 0, $utc),
];
usort($list, fn (CalendarDate $a, CalendarDate $b) => $a->getTimestamp() <=> $b->getTimestamp());

foreach ($list as $d) { echo $d::class, ' ', $d->toGregorian()->format('Y-m-d'), "\n"; }
// RtlyKit\Calendar\Hijri 2025-06-26
// RtlyKit\Calendar\Hebrew 2025-09-23
// RtlyKit\Calendar\Jalali 2026-03-21

اختلاف بین تقویم‌ها

diffInDays() روزهای کامل بین دو لحظه را می‌شمارد و به تقویم کاری ندارد. diffInMonths() و diffInYears() ماه و سال کامل را در تقویمِ شیئی که روی آن صدا می‌زنید می‌شمارند؛ تاریخ دیگر ابتدا در همان تقویم بیان می‌شود. با $absolute = false علامت همان علامت $this - $other است.

$target = Hijri::create(1447, 9, 1, 0, 0, 0, $utc);   // اول رمضان 1447

echo $nowruz->diffInDays($target);          // 31
echo $nowruz->diffInDays($target, false);   // 31   ($nowruz دیرتر از $target است)
echo $target->diffInDays($nowruz, false);   // -31

echo $nowruz->diffInMonths($target);        // 1    (ماه جلالی)
echo Hijri::make($nowruz)->diffInMonths($nowruz->addMonths(3));  // 3  (ماه هجری)
echo $nowruz->diffInYears(Hijri::create(1450, 1, 1, 0, 0, 0, $utc)); // 2

پس «چند ماه مانده» به تقویمی که می‌پرسید بستگی دارد؛ همان تقویمی را انتخاب کنید که کاربرانتان در آن فکر می‌کنند. جدول واحدها برای هر تقویم در جلالی، هجری و عبری آمده است.

موارد مرزی و محدودیت‌ها

  • بازه‌ها. جلالی -620..9377، هجری 1..9665، عبری 3762..13759. تبدیل به تقویمی که بازه‌اش آن لحظه را در بر نمی‌گیرد InvalidDateException پرتاب می‌کند.
  • گونهٔ هجری. تاریخ هجری که به تقویم دیگر و بازمی‌گردد همان لحظه را نگه می‌دارد، ولی گونه همان است که در فراخوانی make() مقصد آمده (به‌طور پیش‌فرض ام‌القری).
  • دقت. جلالی قاعدهٔ حسابی ۳۳ ساله است، نه تقویم نجومی رسمی. دادهٔ ام‌القری برای 1300 تا 1500 هجری قمری از ICU/CLDR آمده و ماه‌به‌ماه با انتشار رسمی راستی‌آزمایی نشده است؛ بیرون از این بازه قواعد حسابی Tabular به کار می‌رود. یادداشت‌های محدودیت شناخته‌شده در صفحه‌های تقویم را ببینید.
  • خطاها. برای مشکلات تقویمی InvalidDateException و برای هر خطای کتابخانه RtlyKit\Exceptions\RtlyKitException را بگیرید (مدیریت خطا).
