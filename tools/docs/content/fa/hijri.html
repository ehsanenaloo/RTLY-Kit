این کلاس چه می‌کند

کلاس RtlyKit\Calendar\Hijri یک مقدار تاریخ‌وزمان تغییرناپذیر در تقویم هجری قمری است. مثل دو کلاس دیگر، یک لحظهٔ DateTimeImmutable را در خود دارد و قرارداد مشترک CalendarDate را پیاده می‌کند (تبدیل و مقایسهٔ تاریخ‌ها). ویژگی خاص هجری گونه (variant) است: قاعده‌ای که طول هر ماه را تعیین می‌کند. هر نمونه گونهٔ خودش را دارد و هر متد تغییردهنده آن را حفظ می‌کند.

همهٔ مثال‌ها این ابتدای فایل را فرض می‌کنند (نصب):

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Hijri;
use RtlyKit\Calendar\HijriVariant;
use RtlyKit\Exceptions\InvalidDateException;
use function RtlyKit\hdate;   // تابع کمکی فضای‌نام‌دار؛ همان Hijri::make()

$utc = new DateTimeZone('UTC');

گونه‌ها: ام‌القری و Tabular

گونهطول ماه‌ها چگونه تعیین می‌شود
HijriVariant::UmmAlQura (پیش‌فرض)جدول طول ماه‌های توکار برای سال‌های 1300 تا 1500 هجری قمری (از 1882-11-12 تا 2077-11-16). بیرون از آن، قواعد Tabular جایگزین می‌شوند.
HijriVariant::Tabularتقویم مدنی حسابی: چرخهٔ ۳۰ ساله با ۱۱ سال کبیسه. برای هر سال قطعی است ولی ممکن است یک یا دو روز با ام‌القری فرق کند.
 
$uq  = Hijri::create(1446, 10, 1, 0, 0, 0, $utc);                       // ام‌القری
$tab = Hijri::create(1446, 10, 1, 0, 0, 0, $utc, HijriVariant::Tabular);

echo $uq->toGregorian()->format('Y-m-d');   // 2025-03-30
echo $tab->toGregorian()->format('Y-m-d');  // 2025-03-31
echo $uq->getVariant()->name;               // UmmAlQura

دو نقطهٔ مرجع دیگر: اول رمضان 1446 برابر 2025-03-01 و اول محرم 1447 برابر 2025-06-26 است (ام‌القری).

محدودیت شناخته‌شده. جدول ام‌القری (1300 تا 1500 هجری قمری) از دادهٔ تقویم islamic-umalqura در ICU/CLDR تولید و با چند تاریخ شناخته‌شده سنجیده شده است؛ ولی ماه‌به‌ماه با انتشار رسمی KACST راستی‌آزمایی نشده است. هیچ‌یک از دو گونه تقویم‌های رؤیت هلال (مثلاً در ایران و مراکش) را بازتولید نمی‌کند و ممکن است یک روز اختلاف داشته باشد. مرز روز نیمه‌شبِ مدنی است، نه غروب. نتیجه را برای تاریخ‌های مناسکی که مرجع رسمی اعلام می‌کند به کار نبرید.

پوشش جدول

بیرون از 1300 تا 1500، create() و make() خطا نمی‌دهند؛ با قواعد Tabular برون‌یابی می‌کنند و ممکن است دو مجموعه‌قاعده در مرز بی‌درز به هم نرسند. با Hijri::hasUmmAlQuraData($year) و $date->usesUmmAlQuraTable() بفهمید کدام قاعده به کار رفته است.

echo Hijri::hasUmmAlQuraData(1299) ? 1 : 0;   // 0
echo Hijri::hasUmmAlQuraData(1300) ? 1 : 0;   // 1
echo Hijri::hasUmmAlQuraData(1500) ? 1 : 0;   // 1
echo Hijri::hasUmmAlQuraData(1501) ? 1 : 0;   // 0

$o = Hijri::create(1600, 1, 1, 0, 0, 0, $utc);
echo $o->toGregorian()->format('Y-m-d');     // 2173-12-06
var_dump($o->usesUmmAlQuraTable());            // bool(false)  (برون‌یابی Tabular)
var_dump(Hijri::create(1446, 9, 1, 0, 0, 0, $utc)->usesUmmAlQuraTable()); // bool(true)

ساخت تاریخ

create()

متد Hijri::create($year, $month, $day, $hour = 0, $minute = 0, $second = 0, $timezone = null, $variant = HijriVariant::UmmAlQura) تاریخ را با طول واقعی ماه در گونهٔ انتخابی اعتبارسنجی می‌کند.

$h = Hijri::create(1446, 9, 1, 0, 0, 0, $utc);

echo $h;                                  // 1446/09/01 00:00:00
echo $h->toGregorian()->format('Y-m-d');  // 2025-03-01
var_dump($h->usesUmmAlQuraTable());       // bool(true)

make() و تابع کمکی

متد Hijri::make($time = null, $timezone = null, $variant = HijriVariant::UmmAlQura) این ورودی‌ها را می‌پذیرد: DateTimeInterface، هر CalendarDate، زمان یونیکس (int)، رشته یا null (اکنون). تابع کمکی hdate($time, $timezone) آن را با گونهٔ پیش‌فرض صدا می‌زند. Hijri::now() و Hijri::today() آرگومان‌های ($timezone, $variant) می‌گیرند.

echo Hijri::make('2025-03-01', $utc);                     // 1446/09/01 00:00:00
echo hdate('2025-03-01')->format('j F Y', 'en');          // 1 Ramadan 1446
echo Hijri::make(Jalali::create(1404, 1, 1, 0, 0, 0, $utc)); // 1446/09/21 00:00:00
echo Hijri::make('2025-03-31', $utc)->format('Y/m/d');    // 1446/10/02
echo Hijri::make('2025-03-31', $utc, HijriVariant::Tabular)->format('Y/m/d'); // 1446/10/01

(خط جلالی به use RtlyKit\Calendar\Jalali; نیاز دارد.)

معنای رشته

  1. ارقام فارسی و عربی به انگلیسی تبدیل و رشته تریم می‌شود؛ رشتهٔ خالی InvalidDateException پرتاب می‌کند.
  2. رشته‌ای به شکل Y/m/d یا Y-m-d (سال ۳ یا ۴ رقمی، اختیاری H:i[:s]) با سال کمتر از 1700 تاریخ هجری در گونهٔ انتخابی خوانده می‌شود.
  3. هر چیز دیگر، از جمله سال‌های 1700 به بعد، میلادی یا متن آزاد پارس می‌شود.
echo Hijri::make('1446/09/01', $utc);   // 1446/09/01 00:00:00   (هجری)
echo Hijri::make('1700/01/01', $utc);   // 1111/07/10 00:00:00   (میلادیِ 1700-01-01)

try { Hijri::make('1446/02/31'); }
catch (InvalidDateException $e) { echo $e->getMessage(); }  // Invalid Hijri date: 1446/2/31
گونهٔ آرگومان هجری. Hijri::make($hijriInstance) همان نمونه را بدون تغییر برمی‌گرداند و آرگومان $variant را نادیده می‌گیرد. برای بیان یک تاریخ در گونهٔ دیگر از لحظه عبور کنید: Hijri::make($h->toGregorian(), null, HijriVariant::Tabular).

بازهٔ پشتیبانی‌شده و خطاها

سال‌های هجری از Hijri::MIN_YEAR = 1 تا Hijri::MAX_YEAR = 9665 پشتیبانی می‌شوند: اولین روز 1/1/1 (0622-07-19) و آخرین روز آخرِ ماه 12 سال 9665 (9999-10-01)، یعنی سال‌های میلادی 622 تا 9999. هر چیز بیرون از این بازه از create()، make()، زمان یونیکس، add*()/sub*() و مبدل‌ها InvalidDateException پرتاب می‌کند؛ هرگز TypeError یا ValueError.

foreach ([[0, 1, 1], [9666, 1, 1], [1446, 1, 31], [1446, 13, 1]] as [$y, $m, $d]) {
    try { Hijri::create($y, $m, $d); }
    catch (InvalidDateException $e) { echo $e->getMessage(), "\n"; }
}
// Invalid Hijri date: 0/1/1
// Invalid Hijri date: 9666/1/1
// Invalid Hijri date: 1446/1/31
// Invalid Hijri date: 1446/13/1

try { Hijri::make(new DateTimeImmutable('0600-01-01', $utc)); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Date out of the supported Hijri range (1..9665): -22

try { Hijri::create(9665, 1, 1)->addYears(1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Hijri year out of the supported range: 9666

خواندن مقدارها

گیرنده‌ها همان‌هایی هستند که قرارداد تعریف می‌کند: getYear()، getMonth()، getDay()، getHour()، getMinute()، getSecond()، getTimestamp()، getTimezone()، toGregorian()، toDateString() (Y/m/d) و toDateTimeString(). هجری دو متد دیگر هم دارد: getVariant() و usesUmmAlQuraTable().

شمارهٔ روز هفته

getDayOfWeek() و توکن w یکشنبه‌محور هستند: 0 = یکشنبه تا 6 = شنبه (مثل PHP). جلالی شنبه‌محور است. توکن N شمارهٔ ISO است: 1 = دوشنبه تا 7 = یکشنبه.

$h = Hijri::create(1446, 9, 1, 0, 0, 0, $utc);   // روز شنبه
echo $h->getDayOfWeek();                         // 6
foreach (range(0, 6) as $i) { echo $h->addDays($i)->getDayOfWeek(); }  // 6012345

قالب‌بندی

format($pattern = 'Y/m/d H:i:s', $locale = 'ar', $digits = 'latin'). مقدار $locale یکی از ar، fa یا en است (مقدار ناشناخته به en برمی‌گردد) و نام ماه، نام روز و نشانگر قبل/بعد از ظهر را تعیین می‌کند. $digits یکی از latin، persian یا arabic است. بک‌اسلش نویسهٔ بعدی را بدون تفسیر می‌نویسد. توجه: زبان پیش‌فرض عربی است.

echo $h->format('l j F Y');                 // السبت 1 رمضان 1446
echo $h->format('l j F Y', 'fa');           // شنبه 1 رمضان 1446
echo $h->format('l j F Y', 'en');           // Saturday 1 Ramadan 1446
echo $h->format('Y/m/d', 'ar', 'arabic');   // ١٤٤٦/٠٩/٠١
echo $h->format('j F Y', 'fa', 'persian');  // ۱ رمضان ۱۴۴۶
echo $h->format('t L z N');                 // 29 0 237 6

$pm = Hijri::create(1446, 9, 1, 15, 0, 0, $utc);
echo $pm->format('g:i a', 'ar');            // 3:00 م
echo $pm->format('g:i A', 'en');            // 3:00 PM

متد استاتیک Hijri::monthName($month, $locale = 'ar') نام ماه را برمی‌گرداند و برای ماهِ بیرون از 1 تا 12 InvalidDateException پرتاب می‌کند:

echo Hijri::monthName(9), ' | ', Hijri::monthName(9, 'fa'), ' | ', Hijri::monthName(9, 'en');
// رمضان | رمضان | Ramadan
// Hijri::monthName(13) throws: Invalid Hijri month: 13

جابه‌جایی و برش

مجموعه متدها همان جلالی است: addDays/Hours/Minutes/Seconds، addMonths، addYears، شکل‌های sub* و startOf/endOf برای روز، ماه و سال. ماه‌ها، ماه هجریِ گونهٔ همان نمونه‌اند و روز به طول ماهِ مقصد کاهش می‌یابد (clamp).

echo Hijri::create(1446, 4, 30, 0, 0, 0, $utc)->addMonths(1);  // 1446/05/29 00:00:00  (کاهش روز)
echo $h->addYears(1);                                          // 1447/09/01 00:00:00
echo $h->subMonths(9);                                         // 1445/12/01 00:00:00
echo $h->addDays(29);                                          // 1446/10/01 00:00:00
echo $h->endOfMonth();                                         // 1446/09/29 23:59:59
echo $h->endOfYear();                                          // 1446/12/29 23:59:59
echo $h->startOfYear();                                        // 1446/01/01 00:00:00
echo $tab->addMonths(1)->getVariant()->name;                  // Tabular  (گونه حفظ می‌شود)

جابه‌جایی به بیرون از سال 1 یا 9665، یا با مقدار نامعقول، InvalidDateException پرتاب می‌کند.

مقایسه و اندازه‌گیری

مقایسه (eq ne gt gte lt lte equals isBefore isAfter between isPast isFuture isToday) روی لحظه‌ها انجام می‌شود و هر تقویمی را می‌پذیرد. diffInDays() روز کامل می‌شمارد؛ diffInMonths() و diffInYears() ماه و سال کامل هجری را در گونهٔ همین نمونه می‌شمارند (تاریخ دیگر ابتدا در همان گونه بیان می‌شود). پرچم $absolute مثل جلالی عمل می‌کند.

echo Hijri::create(1446, 1, 1, 0, 0, 0, $utc)->diffInMonths(Hijri::create(1447, 3, 1, 0, 0, 0, $utc)); // 14
echo Hijri::create(1440, 1, 1, 0, 0, 0, $utc)->diffInYears(Hijri::create(1446, 1, 1, 0, 0, 0, $utc));  // 6
echo $h->diffInDays(Hijri::create(1446, 10, 1, 0, 0, 0, $utc));                                        // 29

نکته‌های کاربردی

  • گونه را یک بار برای کل برنامه انتخاب کنید و همه‌جا همان را بدهید؛ مگر می‌خواهید اختلاف‌های روزانهٔ دو گونه را ببینید، آن‌ها را در یک مقایسه مخلوط نکنید.
  • برای تاریخ‌های 1300 تا 1500 هجری قمری، جدول ام‌القری مرجع این کتابخانه است؛ بیرون از آن نتیجه برون‌یابی حسابی است.
  • تبدیل از و به تقویم‌های دیگر در تبدیل و مقایسهٔ تاریخ‌ها و متدهای Carbon (toHijri()، createFromHijri()) در ماکروهای Carbon آمده است.
