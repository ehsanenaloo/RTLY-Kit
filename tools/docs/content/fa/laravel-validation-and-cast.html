قواعد اعتبارسنجی

پس از نصب بسته (راه‌اندازی لاراول)، هفت قاعده در هر validator، form request یا فراخوانی $request->validate() در دسترس است. این قواعد اعتبارسنج‌هایی را که در صفحه‌های اعتبارسنجی آمده‌اند در بر می‌گیرند.

قاعدهمی‌پذیردجزئیات

shebaشبا / IBAN، با پیشوند IR یا بدون آنشبا و کارت بانکی
bank_cardشمارهٔ کارت بانکی ۱۶ رقمی (بررسی Luhn)شبا و کارت بانکی
iran_mobileشمارهٔ موبایل ایرانموبایل، کد پستی، پلاک

هم‌نامی. mobile واژه‌ای عمومی است. اگر بستهٔ دیگر یا کد خودتان قاعده‌ای با همین نام ثبت کند، همه‌جا از iran_mobile استفاده کنید تا ابهامی نماند.

کاربرد

use Illuminate\Http\Request;

public function store(Request $request)
{
    $data = $request->validate([
        'national_code' => 'required|national_code',
        'mobile'        => 'required|iran_mobile',
        'card'          => 'nullable|bank_card',
        'iban'          => 'nullable|sheba',
        'postal'        => 'required|postal_code',
        'plate'         => 'nullable|vehicle_plate',
    ]);
}

اجرای واقعی با دادهٔ نادرست و زبان fa این خروجی را داد:

// national_code = '1234567890'، mobile = '0912'، iban = 'IR000000000000000000000000'
// card، postal و plate مقدار درست دارند و رد می‌شوند.
//
// national_code: national code کد ملی معتبر نیست.
// mobile: mobile شماره موبایل معتبر نیست.
// iban: iban شماره شبا معتبر نیست.

متن انگلیسی «The national code is not a valid Iranian national code.» است و متن عربی هم موجود است؛ ترجمه‌ها و بازنویسی پیام را ببینید.

چه ورودی‌ای پذیرفته می‌شود

  • رشته‌ها. ارقام فارسی و عربی پذیرفته می‌شوند: ۰۰۱۳۵۴۲۴۱۹ قاعدهٔ national_code را می‌گذراند.
  • عدد صحیح و اعشاری ابتدا به رشته تبدیل می‌شود. مراقب عددهایی باشید که با صفر شروع می‌شوند: عدد JSON با مقدار 13542419 صفرهای ابتدای 0013542419 را از دست داده و رد می‌شود. کد ملی، موبایل و کد پستی را به‌صورت رشته بفرستید.
  • آرایه، شیء و بولی هرگز به اعتبارسنج نمی‌رسند و به‌سادگی قاعده را رد می‌کنند.
  • مقدار تهی. مانند قواعد خود لاراول، رشتهٔ خالی و کلید غایب نادیده گرفته می‌شوند مگر فیلد required باشد. مقدار صریح null رد می‌شود مگر فیلد nullable باشد. با required یا nullable منظورتان را روشن کنید.
$f->make(['n' => '۰۰۱۳۵۴۲۴۱۹'], ['n' => 'national_code'])->passes();          // true
$f->make(['n' => 13542419],      ['n' => 'national_code'])->passes();          // false (صفرهای ابتدا از دست رفته)
$f->make(['n' => null],          ['n' => 'nullable|national_code'])->passes(); // true
$f->make(['n' => null],          ['n' => 'national_code'])->passes();          // false
$f->make(['n' => ''],            ['n' => 'national_code'])->passes();          // true  (نادیده گرفته می‌شود)
$f->make(['n' => ''],            ['n' => 'required|national_code'])->passes(); // false
$f->make([],                     ['n' => 'national_code'])->passes();          // true  (کلید غایب)

اگر دلیل رد شدن مقدار را می‌خواهید (طول نادرست، رقم کنترل غلط، نوع نادرست)، اعتبارسنج‌های مستقل را صدا بزنید که Result ساخت‌یافته برمی‌گردانند؛ مرور اعتبارسنج‌ها را ببینید.

کست Eloquent با نام JalaliCast

کلاس RtlyKit\Laravel\Casts\JalaliCast ستون پایگاه داده را میلادی (Y-m-d H:i:s) نگه می‌دارد، همان‌طور که همهٔ ابزارها انتظار دارند، و ویژگی مدل را به‌صورت یک شیء تغییرناپذیر RtlyKit\Calendar\Jalali نشان می‌دهد.

use Illuminate\Database\Eloquent\Model;
use RtlyKit\Laravel\Casts\JalaliCast;

class Post extends Model
{
    protected $guarded = [];

    protected $casts = [
        'published_at' => JalaliCast::class,
    ];
}

$post = new Post();
$post->published_at = '1404/01/15 10:30';

echo $post->getAttributes()['published_at'];          // 2025-04-04 10:30:00   (مقدار ذخیره‌شده)
echo $post->published_at->format('Y/m/d H:i');        // 1404/01/15 10:30
echo get_class($post->published_at);                  // RtlyKit\Calendar\Jalali
echo $post->published_at->addDays(20)->format('Y/m/d'); // 1404/02/04

نوع ستون همان datetime یا timestamp می‌ماند و مایگریشن تغییری نمی‌کند.

رشته‌ای جلالی خوانده می‌شود که سالش ۱۲۰۰ تا ۱۵۹۹ و جداکننده‌اش / یا - باشد، با ساعت اختیاری HH:MM یا HH:MM:SS پس از فاصله یا T. هر رشتهٔ دیگر مانند تاریخ میلادی از تجزیه‌گر معمول می‌گذرد.

خطاها

ورودی نادرست هنگام انتساب RtlyKit\Exceptions\InvalidDateException پرتاب می‌کند، نه خطای خام PHP:

$post->published_at = '1404/13/01';   // Invalid Jalali date: 1404/13/1
$post->published_at = '1404/07/31';   // Invalid Jalali date: 1404/7/31   (مهر ۳۰ روز دارد)
$post->published_at = 'not a date';   // Unable to parse date: not a date
$post->published_at = 1.5;            // Cannot cast value for 'published_at' to a date.
$post->published_at = ['x'];          // Cannot cast value for 'published_at' to a date.

ورودی کاربر را پیش از رسیدن به مدل اعتبارسنجی کنید (مثال form request را در ادامه ببینید) تا اشتباه تایپی خطای فرم بدهد، نه استثنا. خواندن برای null و رشتهٔ خالی آسان‌گیر است (هر دو null می‌دهند)، اما اگر در پایگاه داده متنِ غیرقابل‌تجزیه باشد، خواندن ویژگی InvalidDateException پرتاب می‌کند.

سریال‌سازی مدل

کلاس‌های Jalali، Hijri و Hebrew پیاده‌ساز JsonSerializable هستند: toJson() در مدلی با ویژگی JalaliCast همان متن (string) $date را می‌دهد، مثلاً {"published_at":"1404/01/01 10:00:00"}. toArray() خود شیء Jalali را نگه می‌دارد؛ برای قالب دیگر خودتان قالب‌بندی کنید.

فرم‌ریکوئست

قاعدهٔ آماده‌ای برای فیلد تاریخ جلالی نیست؛ شکل را با قاعدهٔ regex لاراول یا یک قاعدهٔ سفارشی کوچک بررسی کنید و تبدیل را به کست بسپارید:

public function rules(): array
{
    return [
        'published_at' => ['required', 'regex:/^1[2-5]\d\d[\/-]\d{1,2}[\/-]\d{1,2}$/u'],
    ];
}

الگو برای 1404/01/15 و 1404-1-5 می‌گذرد و برای 2025/01/01 و abc رد می‌شود. تاریخ خوش‌ساخت اما ناممکنی مانند 1404/07/31 باز هم به کست می‌رسد و همان‌جا استثنا می‌دهد؛ اگر کاربر متن آزاد تایپ می‌کند، InvalidDateException را در یک قاعدهٔ سفارشی یا در کنترلر بگیرید.

Blade

کست یک شیء Jalali می‌دهد، پس Blade اصلاً به تابع کمکی نیاز ندارد:

{{ $post->published_at?->format('Y/m/d') }}            {{-- 1404/01/15 --}}
{{ $post->published_at?->format('l j F Y') }}          {{-- جمعه 15 فروردین 1404 --}}
{{ \RtlyKit\to_persian_digits($post->published_at->format('Y/m/d')) }}  {{-- ۱۴۰۴/۰۱/۱۵ --}}

برای ستونی که کست نشده، مثل created_at استاندارد (نمونهٔ Carbon)، از تابع کمکی فضای‌نامی استفاده کنید. توابع فضای‌نامی همیشه بارگیری می‌شوند و ثبت‌نامی لازم ندارند:

{{ \RtlyKit\jdate($post->created_at)->format('Y/m/d H:i') }}   {{-- 1404/01/15 08:00 --}}

اگر زیاد به کار می‌برید، بالای فایل Blade با @php use function RtlyKit\jdate; @endphp واردش کنید. با ماکروهای Carbon همین کار $post->created_at->jformat('Y/m/d') است؛ ماکروهای Carbon را ببینید.

نکته. ویژگی null خودکار قالب‌بندی نمی‌شود: همان‌طور که نشان داده شد از عملگر nullsafe یعنی ?-> استفاده کنید، وگرنه Blade روی null خطا می‌دهد. فهرست کامل حروف قالب در صفحهٔ تقویم جلالی است.
