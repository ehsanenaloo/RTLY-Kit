One instant, three calendars

The three calendar classes (Jalali, Hijri, Hebrew) share one design: each wraps a single DateTimeImmutable instant and only views it in its own calendar. Conversion between calendars therefore never goes through text; it is the same instant read through another set of rules. Two consequences follow from this:

  • Converting a date and converting back gives the same instant.
  • Comparing or subtracting dates of different calendars is always well defined, because they are compared as instants.

All examples use this header:

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Hebrew;
use RtlyKit\Calendar\Hijri;
use RtlyKit\Calendar\Jalali;
use RtlyKit\Contracts\CalendarDate;
use RtlyKit\Exceptions\InvalidDateException;

$utc = new DateTimeZone('UTC');

Converting between calendars

Pass a date to another class's make()

Every make() accepts a CalendarDate (as well as a DateTimeInterface, an int timestamp, a string or null). Pass the date you have to the class you want:

$j = Jalali::create(1405, 1, 1, 12, 0, 0, $utc);

echo Hijri::make($j)->format('Y/m/d F', 'en');    // 1447/10/02 Shawwal
echo Hebrew::make($j)->format('Y/m/d F');          // 5786/07/03 Nisan
echo Jalali::make(Hijri::make($j));                 // 1405/01/01 12:00:00

The time of day and the time zone are carried over. To re-express the result in another zone pass a DateTimeZone as the second argument of make():

$tehran = new DateTimeZone('Asia/Tehran');

$h = Hijri::make($j, $tehran);
echo $h->getTimezone()->getName();      // Asia/Tehran
echo $h->getHour(), ':', $h->getMinute();   // 15:30   (12:00 UTC)
Same-class shortcut. Hijri::make($hijri) and Hebrew::make($hebrew) return the very instance you pass (any time zone or variant argument is ignored). Jalali::make($jalali) returns it too unless you pass a time zone, in which case you get a copy in that zone. To change a Hijri date's variant, go through the instant: Hijri::make($h->toGregorian(), null, HijriVariant::Tabular).

From and to Gregorian

toGregorian() returns the underlying DateTimeImmutable; passing a DateTimeInterface to make() goes the other way. The static converters work on plain integers:

$g = new DateTimeImmutable('2026-03-21 12:00', $utc);

echo json_encode([
    Jalali::gregorianToJalali(2026, 3, 21),
    Hijri::gregorianToHijri(2026, 3, 21),
    Hebrew::gregorianToHebrew(2026, 3, 21),
]);
// [[1405,1,1],[1447,10,2],[5786,7,3]]

echo json_encode(Jalali::jalaliToGregorian(1405, 1, 1));   // [2026,3,21]
echo get_class($j->toGregorian());                         // DateTimeImmutable

The Gregorian year must be 1 to 9999. Each calendar's own range (Jalali -620 to 9377, Hijri 1 to 9665, Hebrew 3762 to 13759) is the part of that span the calendar can represent, so converting an early Gregorian date to Hebrew or Hijri can throw InvalidDateException even though the Gregorian date itself is valid:

try { Hebrew::make(new DateTimeImmutable('0001-01-01', $utc)); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Date out of the supported Hebrew range (3762..13759): 3761

Time zones decide the date

The calendar date of an instant depends on the zone you look at it in. The same moment is still 1 Farvardin 1405 (21 March) in UTC but already 2 Farvardin in Tehran, which is 3.5 hours ahead:

$instant = new DateTimeImmutable('2026-03-21 22:30', $utc);

echo Jalali::make($instant);            // 1405/01/01 22:30:00   (UTC)
echo Jalali::make($instant, $tehran);   // 1405/01/02 02:00:00   (Tehran, +03:30)

Pass an explicit zone whenever the calendar day matters; do not rely on the server default.

The CalendarDate contract

RtlyKit\Contracts\CalendarDate is an interface that extends Stringable and is implemented by Jalali, Hijri and Hebrew. Type-hint it to write code that works with every calendar:

function describe(CalendarDate $d): string
{
    return sprintf('%s %d/%02d/%02d', (new ReflectionClass($d))->getShortName(),
        $d->getYear(), $d->getMonth(), $d->getDay());
}

foreach ([Jalali::class, Hijri::class, Hebrew::class] as $class) {
    echo describe($class::make($g)), "\n";
}
// Jalali 1405/01/01
// Hijri 1447/10/02
// Hebrew 5786/07/03

Guarantees that hold for every implementation:

  • Instances are final and immutable; modifiers return a new object.
  • Every method that takes a date, timestamp or delta throws only InvalidDateException for out-of-range input, never a TypeError or ValueError.
  • format() is declared with the pattern only; each class adds its own optional trailing parameters ($persianDigits for Jalali; $locale and $digits for Hijri; $locale for Hebrew). Through the interface you can call only format($pattern).
  • Weekday numbering is not uniform: Jalali is Saturday-first, Hijri and Hebrew are Sunday-first.
$i = new DateTimeImmutable('2025-10-07', $utc);   // a Tuesday
echo Jalali::make($i)->getDayOfWeek(), ' ', Hijri::make($i)->getDayOfWeek(), ' ', Hebrew::make($i)->getDayOfWeek();
// 3 2 2   (Jalali: Saturday = 0; the others: Sunday = 0)

Comparing across calendars

All comparison methods take CalendarDate|DateTimeInterface and compare timestamps. No conversion is needed first:

$nowruz = Jalali::create(1405, 1, 1, 12, 0, 0, $utc);

var_dump($nowruz->eq(Hijri::make($nowruz)));                     // bool(true)
var_dump($nowruz->eq($nowruz->toGregorian()));                   // bool(true)
var_dump($nowruz->gt(Hebrew::create(5785, 1, 1, 0, 0, 0, $utc)));  // bool(true)
var_dump($nowruz->between(Hijri::create(1447, 8, 1, 0, 0, 0, $utc),
                          Hebrew::create(5787, 1, 1, 0, 0, 0, $utc))); // bool(true)

between($a, $b, $equal = true) accepts the bounds in either order and includes them unless you pass false. Equality is equality of instants: Jalali::create(1405, 1, 1) built in UTC is not equal to the same civil date built in Tehran, because they are 3.5 hours apart.

To sort a mixed list, order by getTimestamp():

$list = [
    Hebrew::create(5786, 1, 1, 0, 0, 0, $utc),
    Jalali::create(1405, 1, 1, 0, 0, 0, $utc),
    Hijri::create(1447, 1, 1, 0, 0, 0, $utc),
];
usort($list, fn (CalendarDate $a, CalendarDate $b) => $a->getTimestamp() <=> $b->getTimestamp());

foreach ($list as $d) { echo $d::class, ' ', $d->toGregorian()->format('Y-m-d'), "\n"; }
// RtlyKit\Calendar\Hijri 2025-06-26
// RtlyKit\Calendar\Hebrew 2025-09-23
// RtlyKit\Calendar\Jalali 2026-03-21

Differences across calendars

diffInDays() counts whole days between the two instants and does not care about calendars. diffInMonths() and diffInYears() count whole months and years of the calendar of the object you call them on; the other date is re-expressed in that calendar first. With $absolute = false the sign is that of $this - $other.

$target = Hijri::create(1447, 9, 1, 0, 0, 0, $utc);   // 1 Ramadan 1447

echo $nowruz->diffInDays($target);          // 31
echo $nowruz->diffInDays($target, false);   // 31   ($nowruz is later than $target)
echo $target->diffInDays($nowruz, false);   // -31

echo $nowruz->diffInMonths($target);        // 1    (Jalali months)
echo Hijri::make($nowruz)->diffInMonths($nowruz->addMonths(3));  // 3  (Hijri months)
echo $nowruz->diffInYears(Hijri::create(1450, 1, 1, 0, 0, 0, $utc)); // 2

So "how many months until X" depends on which calendar you ask in; choose the one your users think in. The unit tables per calendar are in Jalali, Hijri and Hebrew.

Edge cases and limits

  • Ranges. Jalali -620..9377, Hijri 1..9665, Hebrew 3762..13759. Conversion into a calendar whose range does not contain the instant throws InvalidDateException.
  • Hijri variant. A Hijri value converted to another calendar and back keeps the instant, but the variant is that of the target make() call (Umm al-Qura by default).
  • Accuracy. Jalali is the arithmetic 33-year rule, not the astronomical official calendar. Hijri Umm al-Qura data for AH 1300 to 1500 comes from ICU/CLDR and is not verified month by month against the official publication; outside that range the arithmetic Tabular rules apply. See the Known limitation notes on the calendar pages.
  • Errors. Catch InvalidDateException for calendar problems, or RtlyKit\Exceptions\RtlyKitException for any library error (Error handling).
