RequirementStatusNotes
PHP ^8.2RequiredTested in CI on PHP 8.2, 8.3 and 8.4

That is all. In particular, ext-calendar, ext-intl and any database are not needed: the three calendars are implemented in pure PHP, and the Umm al-Qura table ships inside the package.

Install with Composer

composer require enaxon/rtly-kit

Make sure your entry script loads Composer's autoloader, once:

<?php
require __DIR__.'/vendor/autoload.php';

The autoloader maps the RtlyKit\ namespace to the package's src/ directory and also loads one helper file that defines the namespaced helper functions (RtlyKit\jdate() and the others). No global function is defined by that file; see Helpers and globals for the opt-in short names.

Optional packages

composer require nesbot/carbon          # Carbon macros: toJalali(), createFromJalali(), ...
composer require illuminate/support     # only in non-Laravel projects that want the Laravel pieces

Both integrations activate on their own. The Carbon macros register when the autoloader finds Carbon. In a Laravel application the service provider and the Jalali facade alias are found by package auto-discovery, so nothing is added to config/app.php. After installing into an existing Laravel project run php artisan package:discover if your deployment caches discovery.

Install without PHP on your machine (Docker)

If PHP and Composer are not installed locally, run them from official images. From your project directory:

docker run --rm -v "$PWD":/app -w /app composer:2 require enaxon/rtly-kit
docker run --rm -v "$PWD":/app -w /app php:8.3-cli php quick.php

The first command installs the package into vendor/; the second runs a script such as the one in Quick start with PHP 8.3 (the official CLI image includes mbstring). To work on the library itself, clone the repository and use its docker-compose.yml:

docker compose -f tools/docker-compose.yml run --rm php composer install
docker compose -f tools/docker-compose.yml run --rm php composer test
docker compose -f tools/docker-compose.yml run --rm php php -r 'require "vendor/autoload.php"; echo RtlyKit\jdate("2026-03-21")->format("Y/m/d");'

Supported versions

  • PHP 8.2, 8.3 and 8.4 (CI matrix). Newer 8.x releases are expected to work but are not yet in the matrix.
  • Laravel 11 and 12.
  • Carbon 3.
  • Versioning. Before 1.0.0 a minor release may contain breaking changes. Each one is listed in the upgrade guide with migration steps (Upgrade), and the compatibility promise and the list of internal classes are in API stability. Until 1.0.0, pin the minor version in your composer.json constraint (a tilde constraint such as ~0.x.y with the version you tested) and read the upgrade guide before raising it.

Verify the installation

Create verify.php in your project root:

<?php
require __DIR__.'/vendor/autoload.php';

echo PHP_VERSION, "\n";
echo extension_loaded('mbstring') ? "mbstring: yes\n" : "mbstring: NO\n";
echo \RtlyKit\jdate('2026-03-21')->format('Y/m/d'), "\n";   // 1405/01/01

Run php verify.php. The last line must print 1405/01/01; a PHP version below 8.2 or mbstring: NO means the environment does not meet the requirements. Two Composer commands help as well:

composer show enaxon/rtly-kit            # installed version and metadata
composer check-platform-reqs          # checks PHP and extensions against every installed package

If something fails

  • Class "RtlyKit\..." not found or Call to undefined function RtlyKit\jdate(): vendor/autoload.php was not required, or Composer's autoloader is stale; run composer dump-autoload.
  • Call to undefined function jdate() (without the namespace): the short global names are opt-in. Use use function RtlyKit\jdate; or call \RtlyKit\Globals::register().
  • Composer refuses to install and mentions the PHP version or ext-mbstring: install PHP 8.2 or newer, or enable mbstring in php.ini.
  • More cases: Troubleshooting and FAQ.

Uninstall

  1. Remove the package: composer remove enaxon/rtly-kit. This also regenerates the autoloader.
  2. Delete your own usages: use RtlyKit\... and use function RtlyKit\... lines, calls to \RtlyKit\Globals::register(), and any catch blocks for RtlyKit\Exceptions\*. Search your code for RtlyKit to find them all.
  3. Carbon projects: the macros (toJalali, jformat, toHijri, toHebrew, createFromJalali, createFromHijri, createFromHebrew) disappear with the package; replace calls to them first.
  4. Laravel projects: remove the national_code, sheba, bank_card, iran_mobile, mobile, postal_code and vehicle_plate validation rules from your form requests, the JalaliCast from your models, any use of the Jalali facade, and any translation files you copied from the package. Then run php artisan optimize:clear. Data your application already wrote to the database is not touched by removing the package, so check how a cast stored it before you drop the cast.

The package installs nothing outside vendor/ (apart from the Composer lock and autoload metadata), so there is nothing else to clean up.
