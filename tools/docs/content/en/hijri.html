What the class does

RtlyKit\Calendar\Hijri is an immutable date-time value in the Islamic (Hijri) calendar. Like the other calendar classes it wraps one DateTimeImmutable instant and implements the shared CalendarDate contract (see Convert and compare dates). What is specific to Hijri is the variant: the rule set that decides how long each month is. Every instance carries its variant, and every modifier keeps it.

All examples assume this header (see Installation):

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Hijri;
use RtlyKit\Calendar\HijriVariant;
use RtlyKit\Exceptions\InvalidDateException;
use function RtlyKit\hdate;   // namespaced helper, same as Hijri::make()

$utc = new DateTimeZone('UTC');

Variants: Umm al-Qura and Tabular

VariantHow month lengths are decided
HijriVariant::UmmAlQura (default)An embedded month-length table for AH 1300 to 1500 (1882-11-12 to 2077-11-16). Outside it the Tabular rules are used as a fallback.
HijriVariant::TabularThe arithmetic civil calendar: a 30-year cycle with 11 leap years. Deterministic for every year, but it can differ from Umm al-Qura by one or two days.
 
$uq  = Hijri::create(1446, 10, 1, 0, 0, 0, $utc);                       // Umm al-Qura
$tab = Hijri::create(1446, 10, 1, 0, 0, 0, $utc, HijriVariant::Tabular);

echo $uq->toGregorian()->format('Y-m-d');   // 2025-03-30
echo $tab->toGregorian()->format('Y-m-d');  // 2025-03-31
echo $uq->getVariant()->name;               // UmmAlQura

Two further anchors: 1 Ramadan 1446 is 2025-03-01 and 1 Muharram 1447 is 2025-06-26 (Umm al-Qura).

Known limitation. The Umm al-Qura table (AH 1300 to 1500) was generated from the ICU/CLDR islamic-umalqura calendar data and spot-checked against known dates. It has not been verified month by month against the official KACST publication. Neither variant reproduces moon-sighting calendars (used in Iran, Morocco and elsewhere), which can differ by a day. Day boundaries follow civil midnight, not sunset. Do not use the result for religious observance dates that are announced by an authority.

Table coverage

Outside AH 1300 to 1500, create() and make() do not throw: they extrapolate with the Tabular rules, and the two rule sets may not join seamlessly at the border. Use Hijri::hasUmmAlQuraData($year) and $date->usesUmmAlQuraTable() to find out which rule actually applied.

echo Hijri::hasUmmAlQuraData(1299) ? 1 : 0;   // 0
echo Hijri::hasUmmAlQuraData(1300) ? 1 : 0;   // 1
echo Hijri::hasUmmAlQuraData(1500) ? 1 : 0;   // 1
echo Hijri::hasUmmAlQuraData(1501) ? 1 : 0;   // 0

$o = Hijri::create(1600, 1, 1, 0, 0, 0, $utc);
echo $o->toGregorian()->format('Y-m-d');     // 2173-12-06
var_dump($o->usesUmmAlQuraTable());            // bool(false)  (tabular extrapolation)
var_dump(Hijri::create(1446, 9, 1, 0, 0, 0, $utc)->usesUmmAlQuraTable()); // bool(true)

Creating dates

create()

Hijri::create($year, $month, $day, $hour = 0, $minute = 0, $second = 0, $timezone = null, $variant = HijriVariant::UmmAlQura) validates the date against the real month length in the chosen variant.

$h = Hijri::create(1446, 9, 1, 0, 0, 0, $utc);

echo $h;                                  // 1446/09/01 00:00:00
echo $h->toGregorian()->format('Y-m-d');  // 2025-03-01
var_dump($h->usesUmmAlQuraTable());       // bool(true)

make() and the helper

Hijri::make($time = null, $timezone = null, $variant = HijriVariant::UmmAlQura) accepts a DateTimeInterface, any CalendarDate, an int Unix timestamp, a string or null (now). The helper hdate($time, $timezone) calls it with the default variant. Hijri::now() and Hijri::today() take ($timezone, $variant).

echo Hijri::make('2025-03-01', $utc);                     // 1446/09/01 00:00:00
echo hdate('2025-03-01')->format('j F Y', 'en');          // 1 Ramadan 1446
echo Hijri::make(Jalali::create(1404, 1, 1, 0, 0, 0, $utc)); // 1446/09/21 00:00:00
echo Hijri::make('2025-03-31', $utc)->format('Y/m/d');    // 1446/10/02
echo Hijri::make('2025-03-31', $utc, HijriVariant::Tabular)->format('Y/m/d'); // 1446/10/01

(The Jalali line needs use RtlyKit\Calendar\Jalali;.)

String semantics

  1. Persian and Arabic digits become English digits and the string is trimmed; empty strings throw InvalidDateException.
  2. A string of the form Y/m/d or Y-m-d (3 or 4 digit year, optional H:i[:s]) with a year below 1700 is read as a Hijri date in the chosen variant.
  3. Everything else, including years of 1700 or later, is parsed as Gregorian or free-form text.
echo Hijri::make('1446/09/01', $utc);   // 1446/09/01 00:00:00   (Hijri)
echo Hijri::make('1700/01/01', $utc);   // 1111/07/10 00:00:00   (Gregorian 1700-01-01)

try { Hijri::make('1446/02/31'); }
catch (InvalidDateException $e) { echo $e->getMessage(); }  // Invalid Hijri date: 1446/2/31
Variant of a Hijri argument. Hijri::make($hijriInstance) returns that very instance unchanged and ignores the $variant argument. To re-express a date in another variant, go through the instant: Hijri::make($h->toGregorian(), null, HijriVariant::Tabular).

Supported range and errors

Hijri years Hijri::MIN_YEAR = 1 to Hijri::MAX_YEAR = 9665 are supported: the first day is 1/1/1 (0622-07-19) and the last is 9665/12/last (9999-10-01), i.e. Gregorian years 622 to 9999. Anything outside throws InvalidDateException from create(), make(), integer timestamps, add*()/sub*() and the converters; never a TypeError or ValueError.

foreach ([[0, 1, 1], [9666, 1, 1], [1446, 1, 31], [1446, 13, 1]] as [$y, $m, $d]) {
    try { Hijri::create($y, $m, $d); }
    catch (InvalidDateException $e) { echo $e->getMessage(), "\n"; }
}
// Invalid Hijri date: 0/1/1
// Invalid Hijri date: 9666/1/1
// Invalid Hijri date: 1446/1/31
// Invalid Hijri date: 1446/13/1

try { Hijri::make(new DateTimeImmutable('0600-01-01', $utc)); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Date out of the supported Hijri range (1..9665): -22

try { Hijri::create(9665, 1, 1)->addYears(1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Hijri year out of the supported range: 9666

Reading values

The getters are those of the contract: getYear(), getMonth(), getDay(), getHour(), getMinute(), getSecond(), getTimestamp(), getTimezone(), toGregorian(), toDateString() (Y/m/d) and toDateTimeString(). Hijri adds getVariant() and usesUmmAlQuraTable().

Weekday numbering

getDayOfWeek() and the w token are Sunday-first: 0 = Sunday to 6 = Saturday (the same as PHP). Jalali is Saturday-first. The N token is the ISO number, 1 = Monday to 7 = Sunday.

$h = Hijri::create(1446, 9, 1, 0, 0, 0, $utc);   // a Saturday
echo $h->getDayOfWeek();                         // 6
foreach (range(0, 6) as $i) { echo $h->addDays($i)->getDayOfWeek(); }  // 6012345

Formatting

format($pattern = 'Y/m/d H:i:s', $locale = 'ar', $digits = 'latin'). $locale is ar, fa or en (an unknown value falls back to en) and controls month names, weekday names and the AM/PM markers. $digits is latin, persian or arabic. A backslash escapes the next character. Note the default locale is Arabic.

echo $h->format('l j F Y');                 // السبت 1 رمضان 1446
echo $h->format('l j F Y', 'fa');           // شنبه 1 رمضان 1446
echo $h->format('l j F Y', 'en');           // Saturday 1 Ramadan 1446
echo $h->format('Y/m/d', 'ar', 'arabic');   // ١٤٤٦/٠٩/٠١
echo $h->format('j F Y', 'fa', 'persian');  // ۱ رمضان ۱۴۴۶
echo $h->format('t L z N');                 // 29 0 237 6

$pm = Hijri::create(1446, 9, 1, 15, 0, 0, $utc);
echo $pm->format('g:i a', 'ar');            // 3:00 م
echo $pm->format('g:i A', 'en');            // 3:00 PM
TokenMeaning
Y y m n d jYear (4 and 2 digits), month and day with and without leading zero
H G h g i s24-hour and 12-hour clock, minutes, seconds
F MMonth name in the locale
lWeekday name in the locale
w NWeekday number, Sunday = 0; ISO number Monday = 1
z t LZero-based day of the year; days in the month; 1 for a leap year (355 days)
a AAM/PM, locale aware (ص/م, ق.ظ/ب.ظ, am/pm)
S WAlways empty; ISO week of the Gregorian instant

The static Hijri::monthName($month, $locale = 'ar') returns a month name and throws InvalidDateException for a month outside 1 to 12:

echo Hijri::monthName(9), ' | ', Hijri::monthName(9, 'fa'), ' | ', Hijri::monthName(9, 'en');
// رمضان | رمضان | Ramadan
// Hijri::monthName(13) throws: Invalid Hijri month: 13

Shifting and snapping

The method set is that of Jalali: addDays/Hours/Minutes/Seconds, addMonths, addYears, the sub* forms and startOf/endOf for Day, Month and Year. Months are Hijri months of the instance's variant, and the day is clamped to the target month's length.

echo Hijri::create(1446, 4, 30, 0, 0, 0, $utc)->addMonths(1);  // 1446/05/29 00:00:00  (clamped)
echo $h->addYears(1);                                          // 1447/09/01 00:00:00
echo $h->subMonths(9);                                         // 1445/12/01 00:00:00
echo $h->addDays(29);                                          // 1446/10/01 00:00:00
echo $h->endOfMonth();                                         // 1446/09/29 23:59:59
echo $h->endOfYear();                                          // 1446/12/29 23:59:59
echo $h->startOfYear();                                        // 1446/01/01 00:00:00
echo $tab->addMonths(1)->getVariant()->name;                  // Tabular  (variant is kept)

Shifting beyond year 1 or 9665, or by an absurd delta, throws InvalidDateException.

Comparing and measuring

Comparison (eq ne gt gte lt lte equals isBefore isAfter between isPast isFuture isToday) works on instants and accepts any calendar. diffInDays() counts whole days; diffInMonths() and diffInYears() count whole Hijri months and years in this instance's variant (the other date is re-expressed in that variant first). The $absolute flag works as in Jalali.

echo Hijri::create(1446, 1, 1, 0, 0, 0, $utc)->diffInMonths(Hijri::create(1447, 3, 1, 0, 0, 0, $utc)); // 14
echo Hijri::create(1440, 1, 1, 0, 0, 0, $utc)->diffInYears(Hijri::create(1446, 1, 1, 0, 0, 0, $utc));  // 6
echo $h->diffInDays(Hijri::create(1446, 10, 1, 0, 0, 0, $utc));                                        // 29

Calendar arithmetic

echo implode(',', array_map(fn ($m) => Hijri::daysInMonth(1446, $m), range(1, 12)));
// 29,30,30,30,29,30,30,29,29,30,29,29
echo Hijri::daysInYear(1446);                                    // 354
echo Hijri::daysInMonth(1446, 12, HijriVariant::Tabular);        // 29
echo json_encode(Hijri::gregorianToHijri(2025, 3, 1));           // [1446,9,1]
echo json_encode(Hijri::hijriToGregorian(1446, 9, 1));           // [2025,3,1]

Practical notes

  • Choose the variant once per application and pass it everywhere; do not mix variants in one comparison unless you want to see the day-level differences.
  • For dates within AH 1300 to 1500 the Umm al-Qura table is authoritative inside this library; outside it, results are arithmetic extrapolations.
  • Convert from and to the other calendars in Convert and compare dates; Carbon helpers (toHijri(), createFromHijri()) are in Carbon macros.
