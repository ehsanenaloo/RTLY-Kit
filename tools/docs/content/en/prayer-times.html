Overview

RtlyKit\Prayer\PrayerTimes calculates the six daily times from astronomical equations, with no network access and no data file. The solar declination and equation of time come from the low-precision series in Jean Meeus, Astronomical Algorithms (the same equations as the NOAA Solar Calculator). The hour angle comes from spherical trigonometry, Asr from the shadow-length factor, and sunrise/sunset from an altitude of -0.833 degrees (refraction plus the sun's semi-diameter). The Fajr, Maghrib and Isha angles are the published conventions of each method, not values derived from other software.

Results are strings in HH:MM format in the local time of the calculator's time zone, rounded to the nearest minute.

Quick start

use RtlyKit\Prayer\PrayerTimes;

$tz  = new DateTimeZone('Asia/Tehran');
$day = new DateTimeImmutable('2026-03-21 12:00', $tz);

$times = PrayerTimes::forCity('tehran')->getTimes($day);
echo json_encode($times);
// {"fajr":"04:43","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:35","isha":"19:22"}

If you omit the date, getTimes() uses today in the calculator's time zone. The date you pass selects the local calendar day of that zone. There is also a namespaced shortcut that returns the same array for today: \RtlyKit\prayer_times('tehran', 'Tehran') (see helpers and globals).

Creating a calculator

There are two ways to build one.

// 1) A built-in city: coordinates and time zone are filled in.
$p = PrayerTimes::forCity('mecca', PrayerTimes::METHOD_MAKKAH);

// 2) Your own coordinates.
$p = new PrayerTimes(
    latitude:  35.6892,
    longitude: 51.3890,
    method:    PrayerTimes::METHOD_TEHRAN,   // default
    asrFactor: PrayerTimes::ASR_STANDARD,    // default
    timezone:  new DateTimeZone('Asia/Tehran'), // default: date_default_timezone_get()
    elevation: 0.0,                          // metres, default 0
);

forCity() knows these names (case-insensitive): tehran, mashhad, isfahan, shiraz, tabriz, qom, mecca, medina, riyadh, istanbul, cairo, dubai, baghdad, jakarta. Anything else throws, so for other cities use the constructor with your own coordinates.

The same Tehran day computed with each method (only Fajr, Maghrib and Isha differ; sunrise, Dhuhr and Asr do not depend on the method):

foreach (['Tehran', 'MWL', 'ISNA', 'Egypt', 'Makkah', 'Karachi'] as $m) {
    echo str_pad($m, 8), json_encode(PrayerTimes::forCity('tehran', $m)->getTimes($day)), "\n";
}
// Tehran  {"fajr":"04:43","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:35","isha":"19:22"}
// MWL     {"fajr":"04:42","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:37"}
// ISNA    {"fajr":"04:57","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:27"}
// Egypt   {"fajr":"04:34","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:40"}
// Makkah  {"fajr":"04:39","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:47"}
// Karachi {"fajr":"04:42","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:42"}

Dhuhr is solar noon (the sun crossing the meridian); no safety offset is added to any time.

Asr schools

Asr begins when an object's shadow equals its noon shadow plus a multiple of its height. ASR_STANDARD (1, one times the height) is used by the Shafi'i, Maliki, Hanbali and Ja'fari schools; ASR_HANAFI (2, twice the height) gives a later time.

$hanafi = PrayerTimes::forCity('tehran', 'Tehran', PrayerTimes::ASR_HANAFI);
echo $hanafi->getTimes($day)['asr'];   // 16:32  (standard: 15:39)

Makkah: Isha in Ramadan

The Umm al-Qura convention sets Isha at 90 minutes after Maghrib, and at 120 minutes during Ramadan. The calculator picks 120 when the local calendar date falls in Ramadan of the package's own Umm al-Qura Hijri table (month 9), and 90 otherwise. The decision follows the civil date, not a sunset-based Islamic day.

$mk = PrayerTimes::forCity('mecca', 'Makkah');
foreach (['2026-02-20', '2026-03-01', '2026-03-21'] as $s) {
    $t = $mk->getTimes(new DateTimeImmutable($s, new DateTimeZone('Asia/Riyadh')));
    echo $s, ' maghrib ', $t['maghrib'], ' isha ', $t['isha'], "\n";
}
// 2026-02-20 maghrib 18:21 isha 20:21   (+120, Ramadan)
// 2026-03-01 maghrib 18:25 isha 20:25   (+120, Ramadan)
// 2026-03-21 maghrib 18:32 isha 20:02   (+90, after Ramadan)

Elevation

The elevation argument is the observer's height in metres. It lowers the sunrise/sunset altitude by the geometric dip 0.0347 * sqrt(h) degrees, so sunrise is earlier and sunset later on a mountain. Negative values are treated as 0. It affects sunrise, sunset and the times derived from sunset only.

$a = new PrayerTimes(35.6892, 51.3890, 'Tehran', 1, $tz);
$b = new PrayerTimes(35.6892, 51.3890, 'Tehran', 1, $tz, 1500.0);
$d = new DateTimeImmutable('2026-06-21', $tz);
echo $a->getTimes($d)['sunrise'], "\n"; // 04:49
echo $b->getTimes($d)['sunrise'], "\n"; // 04:41

For the Tehran method, Maghrib is defined by the 4.5-degree angle, not by sunset, so it does not change with elevation (19:45 in both cases above).

Time zones and daylight saving

Each time is converted using the zone's real UTC offset at that instant, so a daylight-saving change in the middle of the year is handled without any extra work. Berlin changes on 2026-03-29:

$tzb = new DateTimeZone('Europe/Berlin');
$ber = new PrayerTimes(52.52, 13.405, 'MWL', 1, $tzb);
foreach (['2026-03-28', '2026-03-29'] as $s) {
    echo $s, ' ', json_encode($ber->getTimes(new DateTimeImmutable($s, $tzb))), "\n";
}
// 2026-03-28 {"fajr":"03:51","sunrise":"05:50","dhuhr":"12:11","asr":"15:39","maghrib":"18:34","isha":"20:26"}
// 2026-03-29 {"fajr":"04:48","sunrise":"06:48","dhuhr":"13:11","asr":"16:40","maghrib":"19:35","isha":"21:28"}

Pass the zone that your users read the clock in. If you leave it out, date_default_timezone_get() is used.

The next prayer

nextPrayer() returns the first prayer strictly after a moment (default: now). After Isha it rolls over to tomorrow's Fajr, and date tells you which day the returned prayer falls on.

$p = PrayerTimes::forCity('tehran');
echo json_encode($p->nextPrayer(new DateTimeImmutable('2026-03-21 10:00', $tz)));
// {"name":"dhuhr","time":"12:12","date":"2026-03-21"}
echo json_encode($p->nextPrayer(new DateTimeImmutable('2026-03-21 20:00', $tz)));
// {"name":"fajr","time":"04:42","date":"2026-03-22"}

Note that the sunrise counts as an entry in this sequence (the order is fajr, sunrise, dhuhr, asr, maghrib, isha).

High latitudes

Far from the equator the sun may never reach an angle (no real night in summer). The affected times are returned as null rather than a misleading clamped value. Tromso, 21 June:

$osl = new PrayerTimes(69.65, 18.96, 'MWL', 1, new DateTimeZone('Europe/Oslo'));
echo json_encode($osl->getTimes(new DateTimeImmutable('2026-06-21', new DateTimeZone('Europe/Oslo'))));
// {"fajr":null,"sunrise":null,"dhuhr":"12:46","asr":"17:58","maghrib":null,"isha":null}

Handle the null case in your UI. The library does not apply a high-latitude rule such as "angle-based" or "one-seventh of the night".

Exceptions

Invalid configuration throws InvalidPrayerConfigException, which extends RtlyKitException (and therefore \InvalidArgumentException), for example:

new PrayerTimes(35, 51, 'Foo');
// Unknown calculation method: Foo. Available: MWL, ISNA, Egypt, Makkah, Karachi, Tehran
new PrayerTimes(35, 51, 'MWL', 3);
// Invalid Asr factor: 3 (use 1 or 2)
PrayerTimes::forCity('paris');
// Unknown city: paris

See Error handling for catching all library errors with one catch.

Verification status

The angles are conventions, so the meaningful check is to compare our output for a city and date with the timetable published by the authority that defines the method. Tolerance used: within about 1 minute counts as agreement. Aggregator websites are deliberately not counted as verification, because they use the same published angles.
