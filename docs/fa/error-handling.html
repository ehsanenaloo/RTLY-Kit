دو سبک شکست#

هر تابع در RTLY-Kit دقیقاً یکی از دو سبک زیر را دارد، پس همیشه می‌دانید کجا باید محافظت کنید:

  • اعتبارسنج‌ها هرگز استثنا پرتاب نمی‌کنند. NationalCode، Sheba، BankCard، Mobile، PostalCode و VehiclePlate (و توابع کمکی is_* و validate_*) هر مقداری را می‌پذیرند و با false یا یک Result نامعتبر پاسخ می‌دهند. به مرور اعتبارسنج‌ها نگاه کنید.
  • بقیهٔ توابع استثنا پرتاب می‌کنند؛ یک RtlyKit\Exceptions\RtlyKitException (یا زیرکلاس آن) برای ورودی‌ای که نمی‌پذیرند. برای ورودی بد، هرگز TypeError، ValueError یا استثنای DateMalformed* خود PHP بیرون نمی‌آید؛ اگر دیدید، باگ کتابخانه است و گزارشش کنید.

سلسله‌مراتب استثناها#

\InvalidArgumentException
 └─ RtlyKit\Exceptions\RtlyKitException        implements RtlyKitThrowable
     ├─ InvalidDateException
     ├─ InvalidNumberException
     ├─ InvalidPrayerConfigException
     └─ UnsupportedLocaleException

‏RtlyKitThrowable یک رابط نشانگر است که getErrorCode(): ErrorCode و getContext(): array را تعریف می‌کند. با گرفتن آن (یا RtlyKitException) همهٔ کتابخانه را با یک بلوک catch پوشش می‌دهید. چون RtlyKitException از \InvalidArgumentException ارث می‌برد، کدهای قدیمی که catch (\InvalidArgumentException) یا catch (\LogicException) دارند همچنان کار می‌کنند.

استثناموارد پرتاب
InvalidDateExceptionتاریخ غیرممکن، سال بیرون از بازهٔ پشتیبانی‌شده، رشتهٔ خالی یا غیرقابل‌پارس، مقدار نامعقول در add*() / sub*()، timestamp بیرون از بازه، الگوی قالب‌بندی بیش‌ازحد بلند
InvalidNumberExceptionورودی غیرعددی یا اعشاری، NaN / INF، ورودی بیش‌ازحد بزرگ، عدد خیلی بزرگ، واژه‌های عددی ناشناخته
InvalidPrayerConfigExceptionروش محاسبهٔ ناشناخته، شهر ناشناخته، ضریب عصر نامعتبر
UnsupportedLocaleExceptionزبانی که تابع پشتیبانی نمی‌کند (مثلاً number_to_words(5, 'de'))
خود RtlyKitExceptionسایر آرگومان‌های نامعتبر، مانند جداکنندهٔ نامعتبر یا بلند در Slugify::make() یا نبودِ یک جدول دادهٔ همراه بسته

کدهای خطا#

متن پیام استثنا برای انسان است و ممکن است در هر انتشار بازنویسی شود. بخش پایدار، کد خطا است: یک enum رشته‌ای به نام ErrorCode که نام caseها و مقدارهایش بخشی از API عمومی است (به پایداری API نگاه کنید).

DateOutOfRangedate_out_of_rangeسال، تاریخ، timestamp یا مقدار add*() / sub*() بیرون از بازهٔ پشتیبانی‌شده (به محدودیت‌ها نگاه کنید)

خواندن کد و زمینه (context)#

هر استثنای کتابخانه getErrorCode() و getContext() دارد. context آرایه‌ای از واقعیت‌های ماشین‌خوان دربارهٔ شکست است (یک سقف، زبانِ ناپشتیبانی‌شده، نام آرگومان). هرگز رازی در آن نیست و ممکن است خالی باشد. این اسکریپت پنج ورودی بد را به number_to_words() می‌دهد:

<?php
require __DIR__.'/vendor/autoload.php';

use function RtlyKit\number_to_words;
use RtlyKit\Exceptions\RtlyKitThrowable;

foreach ([1.5, NAN, 'abc', str_repeat('9', 22), str_repeat('1', 5000)] as $input) {
    try {
        number_to_words($input);
    } catch (RtlyKitThrowable $e) {
        echo (new ReflectionClass($e))->getShortName(), ' ',
            $e->getErrorCode()->value, ' ',
            json_encode($e->getContext()), "\n";
    }
}
// InvalidNumberException invalid_number []
// InvalidNumberException non_finite_number []
// InvalidNumberException invalid_number []
// InvalidNumberException number_too_large {"limit":"10^21 - 1"}
// InvalidNumberException input_too_long {"limit":4096}

الگوهای گرفتن استثنا#

بر اساس کد تصمیم بگیرید، نه متن پیام. از match همراه با شاخهٔ default استفاده کنید، چون ممکن است در انتشار فرعی (minor) caseهای تازه‌ای اضافه شود.

<?php
require __DIR__.'/vendor/autoload.php';

use RtlyKit\Calendar\Jalali;
use RtlyKit\Exceptions\{ErrorCode, InvalidDateException, RtlyKitThrowable};

function category(RtlyKitThrowable $e): string
{
    return match ($e->getErrorCode()) {
        ErrorCode::InvalidDate, ErrorCode::DateOutOfRange => 'date',
        ErrorCode::InputTooLong => 'too-long',
        default => 'other',
    };
}

try {
    Jalali::create(1404, 13, 1);          // ماه ۱۳ وجود ندارد
} catch (RtlyKitThrowable $e) {
    echo category($e), "\n";               // date
}

$e = InvalidDateException::because(ErrorCode::DateOutOfRange, 'Year is out of range', ['year' => 99999]);
echo $e->getErrorCode()->value, ' ', json_encode($e->getContext()), "\n";
// date_out_of_range {"year":99999}

try {
    Jalali::create(1404, 13, 1);
} catch (\InvalidArgumentException $e) {   // catch قدیمی هنوز کار می‌کند
    echo get_class($e), ' ', $e instanceof RtlyKitThrowable ? 'is RtlyKitThrowable' : '', "\n";
    // RtlyKit\Exceptions\InvalidDateException is RtlyKitThrowable
}

‏RtlyKitException::because(ErrorCode, string $message, array $context = [], ?Throwable $previous = null) سازندهٔ نام‌دارِ خود کتابخانه برای پرتاب استثنا با کد مشخص است. می‌توانید برای خطاهای خودتان هم از آن استفاده کنید، ولی آنچه شما می‌سازید جزو تعهد کتابخانه نیست.

هنگام ثبت لاگ، کد و context را بنویسید، نه متن پیام را:

catch (RtlyKitThrowable $e) {
    error_log($e->getErrorCode()->value.' '.json_encode($e->getContext()));
}

چه چیزی هرگز استثنا پرتاب نمی‌کند#

اعتبارسنج‌ها هر مقدار PHP را می‌پذیرند. برای ورودی بد، با هر نوع و هر اندازه، استثنا پرتاب نمی‌کنند:

<?php
require __DIR__.'/vendor/autoload.php';

use function RtlyKit\validate_national_code;
use RtlyKit\Validation\Sheba;

var_dump(Sheba::isValid(null));                                  // bool(false)
echo json_encode(validate_national_code([])->errors()), "\n";                    // ["invalid_type"]
echo json_encode(validate_national_code(str_repeat('1', 5000))->errors()), "\n"; // ["input_too_long"]
echo json_encode(validate_national_code('0013542418')->errors()), "\n";          // ["invalid_checksum"]
var_dump(validate_national_code('0013542419')->isValid());       // bool(true)
ورودی اعتبارسنجنتیجه
رشته تا ۴۰۹۶ بایتبه‌طور عادی بررسی می‌شود (ارقام فارسی و عربی پذیرفته است)
int و float صحیحِ متناهیبه رشته تبدیل و سپس بررسی می‌شود (صفرهای ابتدایی در int از قبل از دست رفته‌اند)
null، bool، آرایه، شیء، NaN، INF، float اعشارینامعتبر، با خطای invalid_type
رشته بیش از ۴۰۹۶ بایتنامعتبر، با خطای input_too_long
UTF-8 نامعتبرنامعتبر (معمولاً invalid_format)

قواعد اعتبارسنجی لاراول و Globals::register() هم از همین اصل پیروی می‌کنند: قواعد یک مقدار بولی برمی‌گردانند و Globals::register() هرگز استثنا پرتاب نمی‌کند (نام‌هایی را که رد کرده برمی‌گرداند).

سقف ورودی‌ها#

هر فراخوانی که متن نامطمئن می‌گیرد سقف اندازه دارد تا ورودی مخرب هزینهٔ زیادی نداشته باشد. عبور از سقف، input_too_long را پدید می‌آورد، به‌صورت استثنا یا خطای اعتبارسنج. فهرست کامل در محدودیت‌ها آمده است.

کجاسقفدر صورت عبور
اعتبارسنج‌ها۴۰۹۶ بایت برای هر رشتهResult نامعتبر با خطای input_too_long
ورودی رشته‌ای NumberToWords::convert() / fromWords() و Format۴۰۹۶ بایت برای هر رشتهInvalidNumberException
Format::withSeparator() / format_number()۱۰۰۰ نویسه در عدد اعشاری سادهInvalidNumberException
جداکنندهٔ Slugify::make()۶۴ بایت، UTF-8 معتبرRtlyKitException
الگوی Jalali::format()۲۵۶ بایت (Jalali::MAX_FORMAT_LENGTH)InvalidDateException

قاعدهٔ بازهٔ تقویم#

هر نقطهٔ ورود تقویم (make، create، createFromFormat، timestamp، add* / sub*، توابع کمکی و ماکروهای Carbon) یا تاریخ معتبر برمی‌گرداند یا InvalidDateException پرتاب می‌کند. چیزی سرریز نمی‌شود و نوع دیگری از استثنا به کار نمی‌رود. بازه‌ها: جلالی ‎-620 تا 9377، هجری 1 تا 9665 و عبری 3762 تا 13759، که همه درون سال‌های میلادی 1 تا 9999 هستند. به محدودیت‌ها نگاه کنید.

یک نمونهٔ کامل#

use function RtlyKit\jdate;
use function RtlyKit\number_to_words;
use RtlyKit\Exceptions\InvalidDateException;
use RtlyKit\Exceptions\RtlyKitThrowable;

try {
    $date  = jdate($userInput);
    $words = number_to_words($userAmount);
} catch (InvalidDateException $e) {
    echo "لطفاً تاریخ معتبر وارد کنید.\n";
} catch (RtlyKitThrowable $e) {
    error_log($e->getErrorCode()->value.' '.json_encode($e->getContext()));
}
