محدودیت‌های زیر عمدی‌اند. هر فراخوانی را ارزان و قابل‌پیش‌بینی نگه می‌دارند و نمی‌گذارند ورودی نامطمئن به تاریخ سرریزشده یا محاسبهٔ گران تبدیل شود. عبور از هر کدام همیشه یک RtlyKitException مستند پرتاب می‌کند (به مدیریت خطا نگاه کنید) یا، برای اعتبارسنج‌ها، یک Result نامعتبر می‌دهد.

بازهٔ سال تقویم‌ها#

هر تاریخ پشتیبانی‌شده در هر تقویم به یک سال میلادی بین ۱ و ۹۹۹۹ نگاشت می‌شود؛ پس هر مقداری که کلاس‌ها تولید می‌کنند در یک DateTimeImmutable بدون سرریز جا می‌گیرد. بازه‌ها همان ثابت‌های عمومی MIN_YEAR و MAX_YEAR هستند:

تقویمMIN_YEARMAX_YEARتاریخ میلادیِ ۱/۱ این سال‌ها
Jalali‎-62093770001-03-21 .. 9998-03-20
Hijri196650622-07-19 .. 9998-10-12
Hebrew3762137590001-09-06 .. 9998-10-15
 
<?php
require __DIR__.'/vendor/autoload.php';

use RtlyKit\Calendar\{Hebrew, Hijri, Jalali};

foreach ([Jalali::class, Hijri::class, Hebrew::class] as $class) {
    printf(
        "%-7s %5d..%-5d  %s .. %s\n",
        (new ReflectionClass($class))->getShortName(),
        $class::MIN_YEAR,
        $class::MAX_YEAR,
        $class::create($class::MIN_YEAR, 1, 1)->toGregorian()->format('Y-m-d'),
        $class::create($class::MAX_YEAR, 1, 1)->toGregorian()->format('Y-m-d'),
    );
}
// Jalali   -620..9377   0001-03-21 .. 9998-03-20
// Hijri       1..9665   0622-07-19 .. 9998-10-12
// Hebrew   3762..13759  0001-09-06 .. 9998-10-15

همهٔ نقاط ورود از بازه پیروی می‌کنند: make، create، createFromFormat، timestampهای یونیکس، add*() / sub*() (حتی با مقدارهای بسیار بزرگ)، توابع کمکی و ماکروهای Carbon. مقدار بیرون از بازه InvalidDateException پرتاب می‌کند؛ هیچ‌چیز تاریخ سرریزشده برنمی‌گرداند و TypeError یا ValueError بیرون نمی‌آید.

مقدارهای افزودن و timestamp#

  • مقدار addDays() / subDays() (و ساعت، دقیقه، ثانیه) که از بازهٔ کل تقویم پشتیبانی‌شده بزرگ‌تر باشد (حدود ۳٫۷ میلیون روز، یا همان بازه بر حسب ساعت، دقیقه یا ثانیه) از همان ابتدا با InvalidDateException رد می‌شود؛ مقدار کوچک‌تری که تاریخ را بیرون از سال‌های پشتیبانی‌شده ببرد هم رد می‌شود.
  • timestamp یونیکس باید در سال‌های میلادی ۱ تا ۹۹۹۹ باشد (با کمی تلورانس برای منطقهٔ زمانی)؛ دورتر از آن رد می‌شود.
  • ‏Hebrew::addMonths() و addYears() هر قدر مقدار بزرگ باشد در زمان ثابت اجرا می‌شوند.

آستانهٔ سال در رشته‌ها#

رشته‌ای مانند 1405/01/01 یا 1405-01-01 که به make() یا یک تابع کمکی داده شود، اگر سال کمتر از آستانه باشد تاریخِ خودِ همان تقویم خوانده می‌شود، وگرنه رشتهٔ میلادی:

کلاسسال تقویم خودشدر غیر این صورت
Jalali / jdate()کمتر از 1700میلادی
Hijri / hdate()کمتر از 1700میلادی
Hebrew / hebrew_date()3000 یا بیشترمیلادی

برای دادن تاریخ میلادیِ واقعی زیر آستانه (مثلاً سال ۹۹۹) از DateTimeImmutable استفاده کنید که هیچ‌گاه بازتفسیر نمی‌شود. به پرسش‌های متداول نگاه کنید.

بازهٔ ام‌القری#

  • جدول ماه‌های ام‌القری داخل بسته سال‌های ۱۳۰۰ تا ۱۵۰۰ هجری قمری (از 1882-11-12 تا 2077-11-16) را پوشش می‌دهد. بیرون از آن، و همیشه برای HijriVariant::Tabular، Hijri از قواعد حسابی استفاده می‌کند که ممکن است یک یا دو روز با رؤیت فرق کند. Hijri::hasUmmAlQuraData($year) می‌گوید یک سال پوشش داده شده یا نه.
  • ‏IranHolidays مناسبت‌های اسلامی را فقط در همین بازه گزارش می‌کند. بیرون از آن فقط تعطیلات ثابت جلالی برمی‌گردد.

سقف اندازهٔ ورودی#

کجاسقفدر صورت عبور
اعتبارسنج‌ها (NationalCode، Sheba، BankCard، Mobile، PostalCode، VehiclePlate)۴۰۹۶ بایت برای هر رشتهResult نامعتبر، خطای input_too_long
NumberToWords::convert() و fromWords() (ورودی رشته‌ای)۴۰۹۶ بایت‏InvalidNumberException با input_too_long
ورودی رشته‌ای Format (‏withSeparator())۴۰۹۶ بایت‏InvalidNumberException با input_too_long
Format::withSeparator() / format_number()۱۰۰۰ نویسه در عدد اعشاری ساده (ارقام صحیح و اعشار روی هم)‏InvalidNumberException با input_too_long
جداکنندهٔ Slugify::make()۶۴ بایت، UTF-8 معتبر‏RtlyKitException (‏input_too_long / invalid_argument)
الگوی Jalali::format()۲۵۶ بایت (Jalali::MAX_FORMAT_LENGTH)InvalidDateException

این سقف‌ها بخشی از تعهد کتابخانه‌اند (به پایداری API نگاه کنید).

بازهٔ اعداد#

تابعبازهفراتر از آن
number_to_words($n) (فارسی، پیش‌فرض)عدد صحیح تا ۲۱ رقم (کمتر از 10^21) و منفی‌ها‏InvalidNumberException با number_too_large
number_to_words($n, 'ar')از ۰ تا 999,999,999 و منفی‌ها، فقط شکل شمارشِ مذکر‏InvalidNumberException با number_too_large
number_to_words($n, 'de') یا هر زبان دیگرفقط fa و arUnsupportedLocaleException
NumberToWords::convert()، Format::ordinal()اعداد صحیح؛ floatهای صحیح مانند 3.0 پذیرفته است‏InvalidNumberException برای 1.5، NaN، INF
Format::ordinal()اعداد صحیحِ نامنفیInvalidNumberException
 
use function RtlyKit\number_to_words;

echo number_to_words(999999999, 'ar'), "\n";
// تسعمئة وتسعة وتسعون مليون وتسعمئة وتسعة وتسعون ألف وتسعمئة وتسعة وتسعون
// number_to_words(1000000000, 'ar') استثنای InvalidNumberException پرتاب می‌کند (number_too_large، limit برابر "10^9")
// number_to_words(str_repeat('9', 22)) استثنای InvalidNumberException پرتاب می‌کند (number_too_large، limit برابر "10^21 - 1")
