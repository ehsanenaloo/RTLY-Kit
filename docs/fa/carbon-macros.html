این بخش چه چیزی می‌دهد#

اگر nesbot/carbon نصب باشد، RTLY-Kit چند ماکرو روی Carbon\Carbon و Carbon\CarbonImmutable ثبت می‌کند. با آن‌ها در یک فراخوانی از Carbon به کلاس‌های تقویم و برعکس می‌روید. Carbon اختیاری است: RTLY-Kit آن را الزامی نمی‌کند و بدون Carbon هیچ چیز ثبت نمی‌شود و چیزی خراب نمی‌شود. برنامه‌های لاراول Carbon را همراه دارند و ماکروها بدون کار اضافه در دسترس‌اند (راه‌اندازی لاراول را هم ببینید).

پیش‌نیاز. RTLY-Kit نصب باشد (نصب) و Carbon نسخهٔ 3 (composer require nesbot/carbon؛ نسخهٔ 3 نسخهٔ پشتیبانی‌شده است).

ثبت ماکروها چگونه کار می‌کند#

کامپوزر هنگام بارگذاری خودکار، فایل توابع کمکی بسته را بارگذاری می‌کند. آن فایل یکپارچگی‌ها را راه می‌اندازد، وجود کلاس‌های Carbon را بررسی می‌کند و در صورت وجود، ماکروها را یک بار ثبت می‌کند. شما خودتان چیزی صدا نمی‌زنید:

<?php
require 'vendor/autoload.php';

use Carbon\Carbon;
use Carbon\CarbonImmutable;
use RtlyKit\Calendar\HijriVariant;
use RtlyKit\Calendar\Jalali;

var_dump(Carbon::hasMacro('toJalali'));   // bool(true)
Carbon را با کامپوزر نصب کنید. ماکروها هنگام شروع بارگذار خودکار کامپوزر ثبت می‌شوند و فقط وقتی که کلاس‌های Carbon پیدا شوند. نسخه‌ای از Carbon که روی همان بارگذار نیست (مثلاً phar همراه برنامه) شناسایی نمی‌شود. کلاس‌های ثبت‌کننده داخلی‌اند؛ به نام ماکروها تکیه کنید که بخشی از API عمومی هستند.

مرجع ماکروها#

ماکرونوعخروجیتوضیح
toJalali()نمونه‌ایJalaliهمان لحظه و منطقهٔ زمانیِ شیء Carbon
jformat($format = 'Y/m/d H:i:s')نمونه‌ایstringمیان‌بر toJalali()->format($format)؛ توکن‌ها مثل قالب‌بندی جلالی
toHijri(?HijriVariant $variant = null)نمونه‌ایHijriام‌القری، مگر گونه بدهید
toHebrew()نمونه‌ایHebrew
createFromJalali($y, $m, $d, $h = 0, $i = 0, $s = 0, $tz = null)استاتیککلاسی که روی آن صدا زده‌ایدCarbon:: یک Carbon و CarbonImmutable:: یک CarbonImmutable می‌دهد
createFromHijri($y, $m, $d, $h = 0, $i = 0, $s = 0, $tz = null, ?HijriVariant $variant = null)استاتیککلاسی که روی آن صدا زده‌ایدگونهٔ پیش‌فرض ام‌القری
createFromHebrew($y, $m, $d, $h = 0, $i = 0, $s = 0, $tz = null)استاتیککلاسی که روی آن صدا زده‌ایدشمارهٔ ترتیبی ماه، ماه‌های عبری را ببینید

آرگومان $tz یکی از این‌ها را می‌پذیرد: DateTimeZone، رشتهٔ شناسهٔ منطقهٔ زمانی، یا null (که منطقهٔ پیش‌فرض PHP اعمال می‌شود، نه منطقهٔ یک شیء Carbon موجود).

از Carbon به تقویم#

$c = Carbon::create(2026, 3, 21, 12, 0, 0, 'UTC');

echo $c->toJalali();                           // 1405/01/01 12:00:00
echo get_class($c->toJalali());                // RtlyKit\Calendar\Jalali
echo $c->jformat('l j F Y');                   // شنبه 1 فروردین 1405
echo $c->jformat();                            // 1405/01/01 12:00:00
echo $c->toHijri()->format('j F Y', 'en');     // 2 Shawwal 1447
echo $c->toHebrew()->format('j F Y');          // 3 Nisan 5786

نتیجه شیء تقویم است، نه شیء Carbon؛ از آنجا به بعد از API تقویم استفاده کنید (مثلاً ارقام فارسی با $c->toJalali()->format('Y/m/d', true)). چون شیء تقویم یک مقدار معمولی است، می‌توانید با آن کار کنید و هر زمان با toGregorian() برگردید:

echo Carbon::now('UTC')->setDate(2026, 3, 21)->toJalali()->addMonths(1)->format('Y/m/d');  // 1405/02/01

صدا زدن مستقیم make() تقویم با یک نمونهٔ Carbon معادل است، چون Carbon یک DateTimeInterface است:

echo Jalali::make($c)->format('Y/m/d H:i');                                   // 1405/01/01 12:00
echo Jalali::make(Carbon::create(2026, 3, 21, 22, 0, 0, 'UTC'), new DateTimeZone('Asia/Tehran'))->format('Y/m/d H:i');  // 1405/01/02 01:30

از اجزای تقویم به Carbon#

$a = Carbon::createFromJalali(1405, 1, 1, 0, 0, 0, 'UTC');
echo get_class($a), ' ', $a->toDateTimeString();      // Carbon\Carbon 2026-03-21 00:00:00

$b = CarbonImmutable::createFromJalali(1405, 1, 1, 8, 30, 0, 'Asia/Tehran');
echo get_class($b), ' ', $b->toIso8601String();       // Carbon\CarbonImmutable 2026-03-21T08:30:00+03:30

echo Carbon::createFromHijri(1446, 9, 1, 0, 0, 0, 'UTC')->toDateString();   // 2025-03-01
echo Carbon::createFromHebrew(5786, 1, 1, 0, 0, 0, 'UTC')->toDateString();  // 2025-09-23

گونهٔ Tabular هجری را آخرین آرگومان createFromHijri() بدهید: Carbon::createFromHijri(1446, 10, 1, 0, 0, 0, 'UTC', HijriVariant::Tabular).

خطاها#

ماکروها از طریق کلاس‌های تقویم اعتبارسنجی می‌کنند؛ پس ورودی نامعتبر یا بیرون از بازه RtlyKit\Exceptions\InvalidDateException پرتاب می‌کند (در این موارد هرگز InvalidFormatException کربن)، و شناسهٔ منطقهٔ زمانیِ ناشناخته هم همین‌طور:

use RtlyKit\Exceptions\RtlyKitThrowable;

$cases = [
    fn () => Carbon::createFromJalali(1404, 12, 30),
    fn () => Carbon::createFromJalali(1404, 1, 1, 0, 0, 0, 'Nowhere/Land'),
    fn () => Carbon::createFromHijri(9999, 1, 1),
    fn () => Carbon::createFromHebrew(1, 1, 1),
];
foreach ($cases as $f) {
    try { $f(); }
    catch (RtlyKitThrowable $e) { echo get_class($e), ': ', $e->getMessage(), "\n"; }
}
// RtlyKit\Exceptions\InvalidDateException: Invalid Jalali date: 1404/12/30
// RtlyKit\Exceptions\InvalidDateException: Unknown timezone: Nowhere/Land
// RtlyKit\Exceptions\InvalidDateException: Invalid Hijri date: 9999/1/1
// RtlyKit\Exceptions\InvalidDateException: Invalid Hebrew date: 1/1/1

بازه‌های پشتیبانی همان بازهٔ تقویم‌هاست: جلالی -620..9377، هجری 1..9665، عبری 3762..13759.

محدودیت‌ها و احتیاط‌ها#

محدودیت شناخته‌شده. ماکروها دقت کلاس‌های تقویم را به ارث می‌برند: جلالی قاعدهٔ حسابی ۳۳ ساله است (نه تقویم نجومی رسمی) و دادهٔ ام‌القری برای 1300 تا 1500 هجری قمری از ICU/CLDR آمده و ماه‌به‌ماه با انتشار رسمی راستی‌آزمایی نشده است. مرز روز نیمه‌شب مدنی است.
  • ماکروها برای هر کلاس سراسری‌اند: اگر بستهٔ دیگری ماکرویی با همین نام (toJalali، toHijri ...) تعریف کند، آن که آخر ثبت شود برنده است. وقتی قطعیت می‌خواهید مستقیم از کلاس‌های تقویم استفاده کنید (Jalali::make($carbon)).
  • منطقهٔ زمانی همراه شیء می‌آید: toJalali() از منطقهٔ خود شیء Carbon استفاده می‌کند؛ اگر روز تقویمی مهم است، پیش از تبدیل منطقه را یکسان کنید.
  • شمارهٔ روز هفته بین تقویم‌ها فرق دارد؛ getDayOfWeek() یک تقویم را به تقویم دیگر ندهید. تبدیل و مقایسهٔ تاریخ‌ها را ببینید.
