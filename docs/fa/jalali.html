این کلاس چه می‌کند#

کلاس RtlyKit\Calendar\Jalali یک مقدار تاریخ‌وزمان تغییرناپذیر در تقویم جلالی (شمسی) است. در درون، یک لحظهٔ DateTimeImmutable را نگه می‌دارد؛ بنابراین منطقهٔ زمانی، زمان یونیکس و معادل دقیق میلادی دارد و سال، ماه و روز جلالی از همان لحظه محاسبه می‌شوند. هر متد تغییردهنده یک شیء تازه برمی‌گرداند و شیء اصلی هرگز عوض نمی‌شود. کلاس final است و قرارداد مشترک CalendarDate را پیاده می‌کند که در تبدیل و مقایسهٔ تاریخ‌ها آمده است.

پیش‌نیاز. بسته را نصب کنید (نصب). همهٔ مثال‌ها این ابتدای فایل را فرض می‌کنند:

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Jalali;
use RtlyKit\Exceptions\InvalidDateException;
use function RtlyKit\jdate;   // تابع کمکی فضای‌نام‌دار؛ همان Jalali::make()
محدودیت شناخته‌شده. تبدیل بر پایهٔ قاعدهٔ حسابی چرخهٔ ۳۳ ساله پیاده شده است (سال‌های کبیسه در باقیمانده‌های 1، 5، 9، 13، 17، 22، 26، 30 به پیمانهٔ 33). این همان تقویم نجومی رسمی ایران نیست. برای سال‌های امروزی با تقویم رسمی هم‌خوان است، اما دو قاعده ذاتاً متفاوت‌اند و در سال‌های بسیار دور ممکن است در یک روز کبیسه اختلاف داشته باشند. برای مهلت‌های قانونی که به انتشار رسمی بسته‌اند، این کلاس را مرجع قرار ندهید.

ساخت تاریخ#

از اجزا: create()#

متد create($year, $month, $day, $hour = 0, $minute = 0, $second = 0, $timezone = null) تاریخ را از اجزای جلالی می‌سازد و آن را با طول واقعی ماهِ همان سال اعتبارسنجی می‌کند؛ پس 1404/12/30 (1404 کبیسه نیست) رد می‌شود ولی 1403/12/30 پذیرفته است. اگر منطقهٔ زمانی ندهید، منطقهٔ پیش‌فرض PHP (date_default_timezone_get()) به کار می‌رود.

$tehran = new DateTimeZone('Asia/Tehran');
$d = Jalali::create(1404, 7, 15, 14, 30, 5, $tehran);

echo $d;                                   // 1404/07/15 14:30:05
echo $d->getTimestamp();                   // 1759834805
echo $d->toGregorian()->format('c');       // 2025-10-07T14:30:05+03:30

از هر ورودی: make()#

متد Jalali::make($time = null, $timezone = null) این ورودی‌ها را می‌پذیرد: DateTimeInterface، هر CalendarDate دیگر (هجری، عبری، جلالی)، عدد صحیح زمان یونیکس، رشته یا null (اکنون). تابع کمکی فضای‌نام‌دار jdate() فقط یک نام کوتاه برای آن است.

$utc = new DateTimeZone('UTC');

echo Jalali::make(new DateTimeImmutable('2026-03-21 12:00', $utc)); // 1405/01/01 12:00:00
echo Jalali::make(0, $utc);                                        // 1348/10/11 00:00:00
echo jdate('2026-03-21')->format('l j F Y');                       // شنبه 1 فروردین 1405
echo Jalali::now();      // لحظهٔ کنونی در منطقهٔ پیش‌فرض
echo Jalali::today();    // امروز ساعت 00:00:00

معنای رشته در make()#

رشته‌ها به این ترتیب بررسی می‌شوند:

  1. ارقام فارسی و عربی به انگلیسی تبدیل و رشته تریم می‌شود. رشتهٔ خالی یا فقط‌فاصله، InvalidDateException پرتاب می‌کند.
  2. اگر رشته به شکل Y/m/d یا Y-m-d با سال ۳ یا ۴ رقمی باشد (اختیاری: ساعت H:i یا H:i:s پس از فاصله یا T) و سال کمتر از 1700 باشد، تاریخ جلالی فرض می‌شود.
  3. هر رشتهٔ دیگر، از جمله هر سال 1700 یا بیشتر، به DateTimeImmutable سپرده و میلادی یا متن آزاد خوانده می‌شود ('2025-10-07'، 'tomorrow'، '10 October 2025').
echo Jalali::make('1403/12/30');          // 1403/12/30 00:00:00
echo Jalali::make('۱۴۰۴/۰۷/۱۵');          // 1404/07/15 00:00:00   (ارقام فارسی)
echo Jalali::make('1404-07-15 08:05');    // 1404/07/15 08:05:00
echo Jalali::make('2025-10-07')->format('Y/m/d');  // 1404/07/15   (متن میلادی)
echo Jalali::make('1700/01/01')->format('Y/m/d');  // 1078/10/12   (1700 به بعد میلادی است)
مرز 1700 را به یاد داشته باشید. رشته‌ای مانند '0001-01-01' یا '1500-06-01' تاریخ جلالی خوانده می‌شود، نه میلادی. برای تاریخ میلادی پیش از سال 1700، خودتان یک DateTimeImmutable بسازید و همان شیء را به make() بدهید.

ورودی نامعتبر همیشه InvalidDateException پرتاب می‌کند:

foreach (['1404/12/30', '1404/13/01', '1404/07/15 25:00', '', 'garbage'] as $s) {
    try {
        Jalali::make($s);
    } catch (InvalidDateException $e) {
        echo "'$s': ", $e->getMessage(), "\n";
    }
}
// '1404/12/30': Invalid Jalali date: 1404/12/30
// '1404/13/01': Invalid Jalali date: 1404/13/1
// '1404/07/15 25:00': Invalid time: 25:0:0
// '': Unable to parse an empty date string.
// 'garbage': Unable to parse date: garbage

با قالب: createFromFormat()#

متد Jalali::createFromFormat($format, $time, $timezone = null) با توکن‌های DateTime::createFromFormat پارس می‌کند (ارقام می‌توانند فارسی باشند) ولی سال، ماه و روز را جلالی می‌داند. محدودیت‌های مخصوص میلادی، مثل «فوریه حداکثر ۲۹ روز دارد»، اعمال نمی‌شود و نتیجه را خود تقویم جلالی اعتبارسنجی می‌کند.

echo Jalali::createFromFormat('Y/m/d H:i', '1404/07/15 08:30', $tehran); // 1404/07/15 08:30:00
echo Jalali::createFromFormat('d-m-Y', '31-06-1404');                    // 1404/06/31 00:00:00

try {
    Jalali::createFromFormat('Y/m/d', 'abc');
} catch (InvalidDateException $e) {
    echo $e->getMessage();   // Unable to parse 'abc' with format 'Y/m/d'
}

بازهٔ پشتیبانی‌شده و خطاها#

سال‌های جلالیِ پشتیبانی‌شده از Jalali::MIN_YEAR = -620 تا Jalali::MAX_YEAR = 9377 است؛ دقیقاً همان بازه‌ای که به سال‌های میلادی 1 تا 9999 نگاشت می‌شود: اولین روز -620/01/01 (0001-03-21) و آخرین روز 9377/12/30 (9999-03-20). هر نقطهٔ ورود بازه را بررسی می‌کند و فقط InvalidDateException پرتاب می‌کند، نه TypeError و نه ValueError و نه DateMalformed*؛ این شامل create()، make()، createFromFormat()، زمان یونیکس، add*()/sub*() و مبدل‌های استاتیک است.

foreach ([[-621, 1, 1], [9378, 1, 1], [1404, 12, 30], [1404, 0, 1], [1404, 7, 31]] as [$y, $m, $d]) {
    try {
        Jalali::create($y, $m, $d);
    } catch (InvalidDateException $e) {
        echo $e->getMessage(), "\n";
    }
}
// Invalid Jalali date: -621/1/1
// Invalid Jalali date: 9378/1/1
// Invalid Jalali date: 1404/12/30
// Invalid Jalali date: 1404/0/1
// Invalid Jalali date: 1404/7/31

اجزای زمان هم بررسی می‌شوند: Jalali::create(1404, 1, 1, 24, 0, 0) خطای Invalid time: 24:0:0 می‌دهد. زمان یونیکسِ بیرون از سال‌های میلادی 1 تا 9999 خطای Timestamp out of the supported range: ... می‌دهد.

برای رسیدگی به خطاهای تقویمی فقط InvalidDateException را بگیرید، یا برای همهٔ خطاهای کتابخانه کلاس پایهٔ RtlyKit\Exceptions\RtlyKitException (یا اینترفیس نشانگر RtlyKitThrowable) را. مدیریت خطا را ببینید.

خواندن مقدارها#

متدخروجی

getHour()، getMinute()، getSecond()ساعت، دقیقه و ثانیه در منطقهٔ زمانیِ شیء
getDayOfWeek()0 = شنبه تا 6 = جمعه
monthName()نام فارسی ماه، مثلاً مهر
getTimestamp()، getTimezone()زمان یونیکس و DateTimeZone
toGregorian()DateTimeImmutable زیرین
toDateString()، toDateTimeString()، __toString()Y/m/d، Y/m/d H:i:s، Y/m/d H:i:s

شمارهٔ روز هفته#

هفتهٔ جلالی از شنبه شروع می‌شود: getDayOfWeek() و توکن w برای شنبه 0 و برای جمعه 6 برمی‌گردانند؛ توکن N از 1 (شنبه) تا 7 (جمعه) است. هجری و عبری فرق دارند: یکشنبه‌محورند (0 = یکشنبه)، مثل w خود PHP. شمارهٔ روز هفته را بین تقویم‌ها مقایسه نکنید؛ لحظه‌ها را مقایسه کنید.

$d = Jalali::create(1404, 7, 15);           // سه‌شنبه
foreach (range(0, 6) as $i) {
    $x = $d->addDays($i);
    echo $x->getDayOfWeek(), ':', $x->format('l'), ' ';
}
// 3:سه‌شنبه 4:چهارشنبه 5:پنجشنبه 6:جمعه 0:شنبه 1:یکشنبه 2:دوشنبه

قالب‌بندی#

متد format($pattern = 'Y/m/d H:i:s', $persianDigits = false) توکن‌های سبک date() را در تقویم جلالی ارزیابی می‌کند. با true به‌عنوان آرگومان دوم، همهٔ ارقام فارسی می‌شوند. بک‌اسلش نویسهٔ بعدی را بدون تفسیر می‌نویسد و نویسه‌هایی که توکن نیستند همان‌طور کپی می‌شوند. الگویی بلندتر از Jalali::MAX_FORMAT_LENGTH (256 بایت) InvalidDateException پرتاب می‌کند.

$d = Jalali::create(1404, 7, 15, 14, 30, 5, $tehran);

echo $d->format('l j F Y');            // سه‌شنبه 15 مهر 1404
echo $d->format('Y/m/d', true);        // ۱۴۰۴/۰۷/۱۵
echo $d->format('c');                  // 1404-07-15T14:30:05+03:30
echo $d->format('h:i A');              // 02:30 بعد از ظهر
echo $d->format('g:i a');              // 2:30 ب.ظ
echo $d->format('\Y: Y, \d: d');       // Y: 1404, d: 15
echo $d->format('t L z W N D');        // 30 0 200 41 4 س
توکنمعنی
Y yسال، چهار رقمی و دو رقمی
m nماه با صفر ابتدایی و بدون آن

l Dنام روز هفته؛ D شکل تک‌حرفی است (ش ی د س چ پ ج)

zشمارهٔ روز در سال جلالی، از صفر
t Lتعداد روزهای ماه؛ 1 اگر سال کبیسه باشد
H G h gساعت 24 و 12 ساعته، با صفر ابتدایی و بدون آن
i sدقیقه و ثانیه
a Aق.ظ/ب.ظ و قبل از ظهر/بعد از ظهر
Sهمیشه تهی (فارسی پسوند ترتیبی ندارد)

cY-m-d\TH:i:sP با تاریخ جلالی

U e T P p O Z I u vبه لحظهٔ زیرین واگذار می‌شوند (زمان یونیکس، منطقه، اختلاف ساعت، میکروثانیه، ...)

جابه‌جایی و برش#

هر متد تغییردهنده یک نمونهٔ تازه برمی‌گرداند و منطقهٔ زمانی حفظ می‌شود.

متدرفتار
addDays() subDays()روز کامل روی لحظهٔ زیرین
addHours() addMinutes() addSeconds() و شکل‌های sub*زمان سپری‌شدهٔ دقیق
addMonths() subMonths()ماه تقویمی؛ روز به طول ماهِ مقصد کاهش می‌یابد (clamp)
addYears() subYears()مثل 12 ماه به ازای هر سال؛ ۳۰ اسفندِ سال کبیسه در سال غیرکبیسه ۲۹ اسفند می‌شود
startOfDay() endOfDay()00:00:00 و 23:59:59 همان روز
startOfMonth() endOfMonth()روز اول 00:00:00؛ روز آخر 23:59:59
startOfYear() endOfYear()اول فروردین 00:00:00؛ آخرین روز اسفند 23:59:59
 
$x = Jalali::create(1403, 12, 30);              // آخرین روز یک سال کبیسه
echo $x->addDays(1);                            // 1404/01/01 00:00:00
echo $x->subDays(30);                           // 1403/11/30 00:00:00
echo $x->addHours(30);                          // 1404/01/01 06:00:00
echo $x->addYears(1);                           // 1404/12/29 00:00:00  (کاهش روز)
echo $x->subMonths(13);                         // 1402/11/30 00:00:00
echo Jalali::create(1404, 6, 31)->addMonths(1); // 1404/07/30 00:00:00  (کاهش روز)

$m = Jalali::create(1404, 7, 15, 14, 30, 5);
echo $m->startOfMonth();   // 1404/07/01 00:00:00
echo $m->endOfMonth();     // 1404/07/30 23:59:59
echo $m->startOfYear();    // 1404/01/01 00:00:00
echo $m->endOfYear();      // 1404/12/29 23:59:59

عبور از بازهٔ پشتیبانی یا جابه‌جایی به‌اندازهٔ نامعقول به‌جای چرخش دوباره، InvalidDateException پرتاب می‌کند:

try { Jalali::create(9377, 1, 1)->addYears(1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Jalali year out of the supported range: 9378

try { $x->addDays(PHP_INT_MAX); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Cannot shift a date by 9223372036854775807 days: out of the supported range.

مقایسه و اندازه‌گیری#

متدهای مقایسه (eq ne gt gte lt lte equals isBefore isAfter between isPast isFuture isToday) لحظه‌ها را مقایسه می‌کنند و هر CalendarDate یا DateTimeInterface را می‌پذیرند. پس دو مقدار فقط وقتی برابرند که یک لحظه باشند؛ این به منطقهٔ زمانی بستگی دارد، نه فقط به تاریخ چاپ‌شده.

$a = Jalali::create(1405, 1, 1, 0, 0, 0, $tehran);
var_dump($a->eq(new DateTimeImmutable('2026-03-21 00:00', $tehran))); // bool(true)
var_dump($a->between(Jalali::create(1404, 1, 1), Jalali::create(1406, 1, 1))); // bool(true)
متدمعنی
diffInDays($other, $absolute = true)روز کامل، گرد‌شده به سمت صفر. با false علامت همان علامت $this - $other است
diffInMonths($other, $absolute = true)ماه کامل جلالی؛ روز و ساعتِ روز هم شمرده می‌شود (15 فروردین تا 14 تیر یعنی 2 ماه)
diffInYears($other, $absolute = true)سال کامل جلالی، بر پایهٔ سالگرد
 
$jan = Jalali::create(1404, 1, 1);
$feb = Jalali::create(1404, 2, 1);
echo $jan->diffInDays($feb);                 // 31
echo $jan->diffInDays($feb, false);          // -31
echo Jalali::create(1404, 1, 15)->diffInMonths(Jalali::create(1404, 4, 14)); // 2
echo Jalali::create(1380, 5, 5)->diffInYears(Jalali::create(1404, 5, 4));    // 23
echo Jalali::create(1380, 5, 5)->diffInYears(Jalali::create(1404, 5, 5));    // 24

متدهای استاتیک#

متدخروجی
Jalali::isValid($y, $m, $d)bool؛ برای سال، ماه یا روز بیرون از بازه false است و هرگز پرتاب نمی‌کند
Jalali::isLeapYear($y)کبیسه اگر $y mod 33 یکی از 1، 5، 9، 13، 17، 22، 26، 30 باشد
Jalali::daysInYear($y)365 یا 366
Jalali::daysInMonth($y, $m)31 برای ماه‌های 1 تا 6، 30 برای 7 تا 11، و 29 یا 30 برای اسفند؛ برای شمارهٔ ماه نامعتبر 0
Jalali::gregorianToJalali($gy, $gm, $gd)[سال, ماه, روز]؛ سال میلادی باید 1 تا 9999 باشد
Jalali::jalaliToGregorian($jy, $jm, $jd)[سال, ماه, روز]؛ روز 1 تا 31 برای هر ماه پذیرفته می‌شود و سرریز به جلو می‌رود
 
echo implode(',', array_filter(range(1399, 1410), Jalali::isLeapYear(...))); // 1399,1403,1408
echo Jalali::daysInMonth(1403, 12), ' ', Jalali::daysInMonth(1404, 12);        // 30 29
echo Jalali::daysInYear(1403), ' ', Jalali::daysInYear(1404);                  // 366 365
echo json_encode(Jalali::gregorianToJalali(2026, 3, 21));                      // [1405,1,1]
echo json_encode(Jalali::jalaliToGregorian(1405, 1, 1));                       // [2026,3,21]

try { Jalali::gregorianToJalali(10000, 1, 1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }

نکته‌های کاربردی#

  • منطقهٔ زمانی. تاریخی که بدون منطقه ساخته شود از منطقهٔ پیش‌فرض PHP استفاده می‌کند. هر وقت نتیجه نباید به تنظیم سرور وابسته باشد، یک DateTimeZone به create()/make() بدهید. ساعت، دقیقه و خودِ تاریخ در منطقهٔ همان شیء خوانده می‌شوند.
  • مرز روز. مثل همهٔ این کتابخانه، روز در نیمه‌شبِ مدنیِ منطقهٔ شیء عوض می‌شود.
  • به‌عنوان مقدار. نمونه‌ها Stringable هستند و می‌توان آن‌ها را با خیال راحت به اشتراک گذاشت و در آرایه نگه داشت؛ مرتب‌سازی با getTimestamp() انجام می‌شود.
  • مرتبط. تبدیل به تقویم‌های دیگر و مقایسهٔ بین‌تقویمی در تبدیل و مقایسهٔ تاریخ‌ها؛ یکپارچگی با Carbon در ماکروهای Carbon؛ تعطیلات رسمی ایران در تعطیلات.
