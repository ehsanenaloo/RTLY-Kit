شروع سریع#

<?php
require 'vendor/autoload.php';

use RtlyKit\Validation\BankCard;
use RtlyKit\Validation\Sheba;
use function RtlyKit\is_bank_card;
use function RtlyKit\is_sheba;

var_dump(Sheba::isValid('IR800170000000000000000123'));   // bool(true)
var_dump(is_sheba('800170000000000000000123'));           // bool(true)، IR خودکار افزوده می‌شود
var_dump(BankCard::isValid('6037-9912-3456-7893'));       // bool(true)
var_dump(is_bank_card('۶۰۳۷۹۹۱۲۳۴۵۶۷۸۹۳'));               // bool(true)، ارقام فارسی

echo Sheba::getBankName('IR800170000000000000000123'), "\n";   // بانک ملی ایران
echo BankCard::getBankName('6219861234567898'), "\n";          // بانک سامان

شماره‌های این مثال‌ها ساختگی‌اند: چک‌سام را رد می‌کنند اما به حساب واقعی تعلق ندارند. هر دو کلاس قرارداد Validator را پیاده می‌کنند، برای ورودی بد استثنا نمی‌اندازند و توابع کمکی validate_sheba() و validate_bank_card() را هم دارند.

شبا (IBAN)#

قالب#

شمارهٔ شبا همان IBAN ایرانی است: IR، دو رقم کنترل و یک BBAN ۲۲ رقمی؛ روی‌هم ۲۶ نویسه. سه رقم اول BBAN بانک را مشخص می‌کند.

IR 80 017 0000000000000000123
│  │  │   └─ بقیهٔ BBAN (۱۹ رقم)
│  │  └──── کد بانک (۳ رقم)
│  └─────── ارقام کنترل
└────────── کد کشور

نرمال‌سازی#

Sheba::normalize() حروف را بزرگ می‌کند، ارقام فارسی و عربی را تبدیل می‌کند و فاصله، خط تیره و نیم‌فاصله را حذف می‌کند. رشتهٔ خالصِ دقیقاً ۲۴ رقمی، یعنی شکل رایج «بدون IR» که بانک‌ها چاپ می‌کنند، پیشوند IR می‌گیرد. هر ورودی دیگر همان‌طور که تایپ شده می‌ماند و در بررسی قالب رد می‌شود:

echo Sheba::normalize('800170000000000000000123');        // IR800170000000000000000123
echo Sheba::normalize('ir80 0170 0000');                   // IR8001700000
echo json_encode(Sheba::validate('ir80-0170-0000-0000-0000-0001-23')->isValid());   // true

چه چیزی بررسی می‌شود#

  1. نوع و اندازه (invalid_type، input_too_long).
  2. قالب: IR و پس از آن دقیقاً ۲۴ رقم، وگرنه invalid_format.
  3. چک‌سام ISO 7064 mod-97-10: چهار نویسهٔ اول به انتها می‌روند، I و R به ۱۸ و ۲۷ تبدیل می‌شوند و عدد حاصل به پیمانهٔ ۹۷ باید برابر ۱ باشد؛ وگرنه invalid_checksum.

جست‌وجوی بانک پیش از چک‌سام انجام می‌شود؛ بنابراین کد بانک حتی برای شمارهٔ دارای رقم کنترل غلط هم در details() هست:

$r = Sheba::validate('IR060170000000000000000123');
var_dump($r->isValid());       // bool(false)
print_r($r->errors());         // Array ( [0] => invalid_checksum )
echo $r->details()['bank_name']; // بانک ملی ایران

$ok = Sheba::validate('IR800170000000000000000123');
echo json_encode($ok->details(), JSON_UNESCAPED_UNICODE);
// {"normalized":"IR800170000000000000000123","bank_code":"017","bank_name":"بانک ملی ایران"}

$unknown = Sheba::validate('IR049990000000000000000123');
var_dump($unknown->isValid(), $unknown->details()['bank_name']);   // bool(true)  NULL

جزئیات: normalized، bank_code (رشتهٔ سه‌رقمی، یا null اگر قالب رد شده باشد) و bank_name (یا null وقتی کد در جدول نیست). شبای دارای چک‌سام درست با کد بانک ناشناخته معتبر است؛ فقط نام ندارد.

نام بانک‌ها. نام‌ها همان نام بانک صادرکننده در زمان تخصیص است. کد بانک‌هایی که بعداً ادغام شده‌اند نام اولیه‌شان را نگه می‌دارد.

شمارهٔ کارت بانکی#

قالب و بررسی‌ها#

کارت بانکی ایران ۱۶ رقم دارد. BankCard::normalize() پس از تبدیل ارقام فارسی و عربی فقط رقم‌ها را نگه می‌دارد؛ پس فاصله، خط تیره و هر جداکنندهٔ دیگر آزاد است. بررسی‌ها به ترتیب:

  1. نوع و اندازه.
  2. دقیقاً ۱۶ رقم، وگرنه invalid_format.
  3. یکسان بودن هر ۱۶ رقم (مثلاً 0000000000000000) repeated_digits می‌دهد.
  4. چک‌سام Luhn، وگرنه invalid_checksum. از سمت راست هر رقم دوم دو برابر می‌شود (اگر حاصل از ۹ بیشتر شد ۹ کم می‌شود) و مجموع ارقام باید بر ۱۰ بخش‌پذیر باشد.
$ok = BankCard::validate('6037-9912 3456 7893');
echo json_encode($ok->details(), JSON_UNESCAPED_UNICODE);
// {"normalized":"6037991234567893","bin":"603799","bank_name":"بانک ملی ایران"}

print_r(BankCard::validate('6037991234567890')->errors());   // [invalid_checksum]
print_r(BankCard::validate('0000000000000000')->errors());   // [repeated_digits]
print_r(BankCard::validate('1234')->errors());               // [invalid_format]

$x = BankCard::validate('9999991234567893');   // چک‌سام درست، BIN در جدول نیست
var_dump($x->isValid(), $x->details()['bank_name']);   // bool(true)  NULL

جزئیات: normalized، bin (شش رقم اول، یا null اگر قالب رد شده باشد) و bank_name. مانند شبا، جست‌وجوی BIN پیش از بررسی تکرار ارقام و چک‌سام انجام می‌شود.

BankCard::getBankName() و Sheba::getBankName() میان‌برهایی‌اند که فقط برای شمارهٔ معتبر نام را برمی‌گردانند و در غیر این صورت null:

var_dump(BankCard::getBankName('6037991234567890'));   // NULL، چون چک‌سام رد می‌شود
var_dump(BankCard::getBankName('6037991234567893'));   // string(26) "بانک ملی ایران"

داده‌های تشخیص بانک#

جدولکلیدتعداد مورد
BIN کارتشش رقم اول کارت۳۹
کد بانک شباسه رقم پس از IRkk۳۸

یک مورد فقط وقتی وارد جدول شده که دست‌کم دو منبع مستقل (جدول‌های عمومی پیش‌شمارهٔ بانک‌ها و مجموعه‌دادهٔ جامعهٔ توسعه‌دهندگان) بر نگاشت آن موافق باشند. موردهای تک‌منبعی یا متناقض عمداً کنار گذاشته شده‌اند.

محدودیت شناخته‌شده. جدول‌ها کوچک و «تا حد امکان درست»‌اند. بسیاری از کارت‌های معتبر از بانکی هستند که در فهرست نیست و برای آن‌ها bank_name برابر null است. بعضی منبع‌های جامعه ریشهٔ مشترک دارند؛ پس توافقشان قوی است اما کاملاً مستقل نیست. جدول رسمی بانک مرکزی هنگام گردآوری داده در دسترس نبود (چند کد شبا فقط با دو منبع تأیید شده است). بانک‌ها ادغام می‌شوند، نام عوض می‌کنند و بازه‌ها را دوباره تخصیص می‌دهند؛ داده در تاریخ ۲۰۲۶-۱۰-۰۷ بررسی شده و با گذر زمان قدیمی می‌شود. نام بانک را اشارهٔ نمایشی بدانید و برای تصمیم حقوقی یا مالی به کار نبرید. جزئیات در دقت و داده‌ها آمده است.

اعتبار هیچ‌وقت به این جدول‌ها بستگی ندارد. شمارهٔ دارای چک‌سام درست معتبر است، چه بانکش شناخته باشد چه نه.

نکات عملی#

  • چک‌سام اشتباه تایپی را می‌گیرد، نه شمارهٔ جعلی را. نمی‌تواند بگوید کارتی وجود دارد یا حسابی به کسی تعلق دارد.
  • شمارهٔ کارت را فقط برای قالب بررسی کنید. شمارهٔ کامل کارت را لاگ نکنید و CVV2 یا رمز دوم را ذخیره نکنید.
  • مقدار نرمال‌شده را ذخیره کنید تا 6037-9912-3456-7893 و 6037991234567893 یک رکورد باشند.
  • شمارهٔ کارت و شبا باید رشته بمانند. عدد ۱۶ رقمی ممکن است از دقت عدد JSON یا اعشاری بیشتر باشد.

سقف اندازه و قاعده‌های نوع مثل همهٔ اعتبارسنج‌هاست؛ پردازش ورودی را ببینید.
