معرفی#

کلاس RtlyKit\Prayer\PrayerTimes شش وقت روزانه را با معادلات نجومی حساب می‌کند، بدون نیاز به اینترنت و بدون فایل داده. میل خورشید و معادلهٔ زمان از سری‌های کم‌دقت ژان میوس در کتاب Astronomical Algorithms گرفته شده‌اند (همان معادلات ماشین‌حساب خورشیدی NOAA). زاویهٔ ساعتی با مثلثات کروی، عصر با ضریب طول سایه و طلوع/غروب با ارتفاع ‎-0.833 درجه (شکست نور به‌علاوهٔ نیم‌قطر خورشید) به‌دست می‌آید. زاویه‌های صبح، مغرب و عشا قراردادهای منتشرشدهٔ هر روش‌اند، نه مقادیری که از نرم‌افزار دیگری مشتق شده باشند.

نتیجه رشته‌هایی به شکل HH:MM به وقت محلی منطقهٔ زمانی محاسبه‌گر است و به نزدیک‌ترین دقیقه گرد می‌شود.

شروع سریع#

use RtlyKit\Prayer\PrayerTimes;

$tz  = new DateTimeZone('Asia/Tehran');
$day = new DateTimeImmutable('2026-03-21 12:00', $tz);

$times = PrayerTimes::forCity('tehran')->getTimes($day);
echo json_encode($times);
// {"fajr":"04:43","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:35","isha":"19:22"}

اگر تاریخ ندهید، getTimes() امروز را در منطقهٔ زمانی محاسبه‌گر برمی‌دارد. تاریخی که می‌دهید روز تقویمی محلی همان منطقه را مشخص می‌کند. میان‌بر فضای‌نامی هم هست که برای امروز همین آرایه را می‌دهد: \RtlyKit\prayer_times('tehran', 'Tehran') (توابع کمکی و سراسری).

ساخت محاسبه‌گر#

دو راه برای ساخت وجود دارد.

// ۱) شهر داخلی: مختصات و منطقهٔ زمانی خودکار پر می‌شود.
$p = PrayerTimes::forCity('mecca', PrayerTimes::METHOD_MAKKAH);

// ۲) مختصات دلخواه.
$p = new PrayerTimes(
    latitude:  35.6892,
    longitude: 51.3890,
    method:    PrayerTimes::METHOD_TEHRAN,   // پیش‌فرض
    asrFactor: PrayerTimes::ASR_STANDARD,    // پیش‌فرض
    timezone:  new DateTimeZone('Asia/Tehran'), // پیش‌فرض: date_default_timezone_get()
    elevation: 0.0,                          // متر، پیش‌فرض ۰
);

تابع forCity() این نام‌ها را می‌شناسد (بدون حساسیت به حروف): ‎tehran، mashhad، isfahan، shiraz، tabriz، qom، mecca، medina، riyadh، istanbul، cairo، dubai، baghdad، jakarta. نام دیگر خطا می‌دهد؛ برای شهرهای دیگر سازنده را با مختصات خودتان به کار ببرید.

روش‌ها و زاویه‌ها#

روش، زاویهٔ فرورفتن خورشید را برای صبح و عشا (و در تهران برای مغرب) تعیین می‌کند. به‌جای رشته از ثابت‌های کلاس استفاده کنید.

ثابتصبحمغربعشا
METHOD_TEHRAN (‎Tehran، پیش‌فرض)۱۷٫۷ درجهخورشید ۴٫۵ درجه زیر افق۱۴ درجه
METHOD_MWL (‎MWL)۱۸ درجهغروب۱۷ درجه
METHOD_ISNA (‎ISNA)۱۵ درجهغروب۱۵ درجه
METHOD_EGYPT (‎Egypt)۱۹٫۵ درجهغروب۱۷٫۵ درجه
METHOD_MAKKAH (‎Makkah)۱۸٫۵ درجهغروبمغرب + ۹۰ دقیقه (در رمضان + ۱۲۰ دقیقه)
METHOD_KARACHI (‎Karachi)۱۸ درجهغروب۱۸ درجه

همان روز تهران با هر روش (فقط صبح، مغرب و عشا فرق می‌کنند؛ طلوع، ظهر و عصر به روش بستگی ندارند):

foreach (['Tehran', 'MWL', 'ISNA', 'Egypt', 'Makkah', 'Karachi'] as $m) {
    echo str_pad($m, 8), json_encode(PrayerTimes::forCity('tehran', $m)->getTimes($day)), "\n";
}
// Tehran  {"fajr":"04:43","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:35","isha":"19:22"}
// MWL     {"fajr":"04:42","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:37"}
// ISNA    {"fajr":"04:57","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:27"}
// Egypt   {"fajr":"04:34","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:40"}
// Makkah  {"fajr":"04:39","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:47"}
// Karachi {"fajr":"04:42","sunrise":"06:07","dhuhr":"12:12","asr":"15:39","maghrib":"18:17","isha":"19:42"}

ظهر همان عبور خورشید از نصف‌النهار است و هیچ زمان احتیاطی به هیچ‌یک از وقت‌ها اضافه نمی‌شود.

مذهب‌های عصر#

عصر وقتی آغاز می‌شود که سایهٔ جسم برابر سایهٔ ظهر به‌علاوهٔ مضربی از ارتفاع آن شود. ASR_STANDARD (مقدار ۱، یک برابر ارتفاع) برای شافعی، مالکی، حنبلی و جعفری است و ASR_HANAFI (مقدار ۲، دو برابر ارتفاع) وقت دیرتری می‌دهد.

$hanafi = PrayerTimes::forCity('tehran', 'Tehran', PrayerTimes::ASR_HANAFI);
echo $hanafi->getTimes($day)['asr'];   // 16:32  (استاندارد: 15:39)

مکه: عشا در رمضان#

قرارداد ام‌القری عشا را ۹۰ دقیقه پس از مغرب و در ماه رمضان ۱۲۰ دقیقه پس از مغرب می‌گذارد. محاسبه‌گر وقتی روز تقویمی محلی در رمضانِ جدول ام‌القریِ خود کتابخانه (ماه ۹) باشد ۱۲۰ و در غیر این صورت ۹۰ را برمی‌دارد. تصمیم بر پایهٔ تاریخ مدنی است، نه روز اسلامی که از غروب شروع می‌شود.

$mk = PrayerTimes::forCity('mecca', 'Makkah');
foreach (['2026-02-20', '2026-03-01', '2026-03-21'] as $s) {
    $t = $mk->getTimes(new DateTimeImmutable($s, new DateTimeZone('Asia/Riyadh')));
    echo $s, ' maghrib ', $t['maghrib'], ' isha ', $t['isha'], "\n";
}
// 2026-02-20 maghrib 18:21 isha 20:21   (+120، رمضان)
// 2026-03-01 maghrib 18:25 isha 20:25   (+120، رمضان)
// 2026-03-21 maghrib 18:32 isha 20:02   (+90، پس از رمضان)

ارتفاع از سطح دریا#

آرگومان elevation ارتفاع ناظر بر حسب متر است. ارتفاع طلوع/غروب را به‌اندازهٔ فرورفتگی هندسی افق، یعنی 0.0347 * sqrt(h) درجه، کم می‌کند؛ پس بر بلندی طلوع زودتر و غروب دیرتر می‌شود. مقدار منفی صفر در نظر گرفته می‌شود. اثر آن فقط بر طلوع، غروب و وقت‌هایی است که از غروب مشتق می‌شوند.

$a = new PrayerTimes(35.6892, 51.3890, 'Tehran', 1, $tz);
$b = new PrayerTimes(35.6892, 51.3890, 'Tehran', 1, $tz, 1500.0);
$d = new DateTimeImmutable('2026-06-21', $tz);
echo $a->getTimes($d)['sunrise'], "\n"; // 04:49
echo $b->getTimes($d)['sunrise'], "\n"; // 04:41

در روش تهران مغرب با زاویهٔ ۴٫۵ درجه تعریف می‌شود نه با غروب، پس با ارتفاع تغییر نمی‌کند (در هر دو حالت بالا ‎19:45).

منطقهٔ زمانی و ساعت تابستانی#

هر وقت با اختلاف واقعی UTC همان لحظه به وقت محلی تبدیل می‌شود، بنابراین تغییر ساعت تابستانی در میانهٔ سال بدون کار اضافه درست کار می‌کند. برلین در ۲۹ مارس ۲۰۲۶ ساعت را تغییر می‌دهد:

$tzb = new DateTimeZone('Europe/Berlin');
$ber = new PrayerTimes(52.52, 13.405, 'MWL', 1, $tzb);
foreach (['2026-03-28', '2026-03-29'] as $s) {
    echo $s, ' ', json_encode($ber->getTimes(new DateTimeImmutable($s, $tzb))), "\n";
}
// 2026-03-28 {"fajr":"03:51","sunrise":"05:50","dhuhr":"12:11","asr":"15:39","maghrib":"18:34","isha":"20:26"}
// 2026-03-29 {"fajr":"04:48","sunrise":"06:48","dhuhr":"13:11","asr":"16:40","maghrib":"19:35","isha":"21:28"}

منطقه‌ای را بدهید که کاربران شما ساعتشان را با آن می‌خوانند. اگر ندهید date_default_timezone_get() به کار می‌رود.

نماز بعدی#

متد nextPrayer() نخستین نماز را که کاملاً پس از یک لحظه (پیش‌فرض: اکنون) باشد برمی‌گرداند. پس از عشا به اذان صبح فردا می‌رود و date نشان می‌دهد نمازِ برگشتی در کدام روز است.

$p = PrayerTimes::forCity('tehran');
echo json_encode($p->nextPrayer(new DateTimeImmutable('2026-03-21 10:00', $tz)));
// {"name":"dhuhr","time":"12:12","date":"2026-03-21"}
echo json_encode($p->nextPrayer(new DateTimeImmutable('2026-03-21 20:00', $tz)));
// {"name":"fajr","time":"04:42","date":"2026-03-22"}

توجه کنید که طلوع هم در این ترتیب یک ورودی است (ترتیب: fajr، sunrise، dhuhr، asr، maghrib، isha).

عرض‌های جغرافیایی بالا#

در عرض‌های بالا ممکن است خورشید هرگز به یک زاویه نرسد (در تابستان شب واقعی نیست). در این حالت زمان‌های مربوط null برمی‌گردند و مقدار گمراه‌کنندهٔ جایگزین داده نمی‌شود. ترومسو، ۲۱ ژوئن:

$osl = new PrayerTimes(69.65, 18.96, 'MWL', 1, new DateTimeZone('Europe/Oslo'));
echo json_encode($osl->getTimes(new DateTimeImmutable('2026-06-21', new DateTimeZone('Europe/Oslo'))));
// {"fajr":null,"sunrise":null,"dhuhr":"12:46","asr":"17:58","maghrib":null,"isha":null}

حالت null را در رابط کاربری مدیریت کنید. کتابخانه قاعدهٔ عرض بالا (مثل «بر پایهٔ زاویه» یا «یک‌هفتم شب») اعمال نمی‌کند.

استثناها#

پیکربندی نامعتبر InvalidPrayerConfigException پرتاب می‌کند که از RtlyKitException (و از این رو از \InvalidArgumentException) ارث می‌برد، مثلاً:

new PrayerTimes(35, 51, 'Foo');
// Unknown calculation method: Foo. Available: MWL, ISNA, Egypt, Makkah, Karachi, Tehran
new PrayerTimes(35, 51, 'MWL', 3);
// Invalid Asr factor: 3 (use 1 or 2)
PrayerTimes::forCity('paris');
// Unknown city: paris

برای گرفتن همهٔ خطاهای کتابخانه با یک catch، مدیریت خطا را ببینید.

وضعیت راستی‌آزمایی#

زاویه‌ها قرارداد هستند، پس بررسی معنادار این است که خروجی ما برای یک شهر و تاریخ با جدول منتشرشدهٔ مرجعِ تعریف‌کنندهٔ آن روش مقایسه شود. معیار: اختلاف تا حدود ۱ دقیقه همخوانی حساب می‌شود. سایت‌های تجمیع‌کننده عمداً شمرده نشده‌اند، چون همان زاویه‌های منتشرشده را به کار می‌برند.

روشوضعیتبیشترین اختلافمرجع و کاستی‌ها
تهرانصبح، طلوع، ظهر و مغرب راستی‌آزمایی شده۱ دقیقه (شیراز)، در بقیه ۰مؤسسهٔ ژئوفیزیک دانشگاه تهران، جدول‌های ۱۴۰۵: تهران، مشهد، اصفهان و شیراز در چهار تاریخ. این جدول‌ها عصر و عشا ندارند، پس عشای ۱۴ درجه و عصر با جدول مرجع پوشش داده نشده‌اند.
مکهراستی‌آزمایی شده، از جمله عشای رمضان۱ دقیقهتقویم ام‌القری: پنج تاریخ بیرون از رمضان و دو تاریخ رمضان ۱۴۴۷ که عشا = مغرب + ۱۲۰ را تأیید می‌کنند.
طلوع و غروبراستی‌آزمایی شده۱ دقیقه۱۱ جفت شهر/تاریخ در برابر timeanddate.
مصرهمخوان، شواهد ضعیف‌تر۱ دقیقهدارالافتاء، قاهره: سه تاریخ در یک فصل. ناشر منبع زاویه را نام نمی‌برد.
کراچیراستی‌آزمایی نشدهنداردجدول رسمی پیدا نشد.
MWLراستی‌آزمایی نشدهندارداین روش فقط زاویه تعریف می‌کند و جدول شهری منتشر نمی‌کند.
ISNAراستی‌آزمایی نشدهنداردمانند MWL.
محدودیت شناخته‌شده. راستی‌آزمایی‌نشده یعنی نادرست نیست: کراچی، MWL و ISNA همان زاویه‌های منتشرشده را با همان مدل خورشیدیِ همخوان با روش‌های تأییدشده به کار می‌برند؛ فقط جدول رسمی برای مقایسه در دسترس نبود. آزمون نشده‌اند: عصر به روش حنفی، عرض‌های بالا، ارتفاع و تاریخ‌های بیرون از فهرست بالا. برای استفادهٔ شرعی یا حقوقی با جدول مرجع محلی خود تطبیق دهید.

روش تهران با جدول‌های مؤسسهٔ ژئوفیزیک همخوان است، اما زاویه‌های ۱۷٫۷ درجه (صبح) و ۴٫۵ درجه (مغرب) در اینجا فقط با همین همخوانی عددی تأیید شده‌اند، نه با توضیح خود مرجع دربارهٔ روشش.
