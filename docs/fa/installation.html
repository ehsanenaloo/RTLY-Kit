پیش‌نیازها#

نیازمندیوضعیتتوضیح
PHP ^8.2الزامیدر CI روی PHP 8.2، 8.3 و 8.4 آزموده می‌شود
ext-mbstringالزامیدر بیلدهای استاندارد PHP فعال است؛ ordinal()، Slugify و ابزارهای متنی از آن استفاده می‌کنند
Composer 2برای نصب لازم استبارگذاری خودکار را انجام می‌دهد؛ بسته هیچ وابستگی الزامی کامپوزری ندارد
nesbot/carbon ^3.0اختیاریماکروهای Carbon را فعال می‌کند
illuminate/support ^11 یا ^12اختیاریکشف خودکار لاراول، فاساد، قواعد اعتبارسنجی و کست Eloquent (راه‌اندازی لاراول)

همین. به‌ویژه، ext-calendar، ext-intl و پایگاه داده لازم نیست: سه تقویم با PHP خالص نوشته شده‌اند و جدول ام‌القری درون بسته است.

نصب با کامپوزر#

composer require enaxon/rtly-kit

مطمئن شوید اسکریپت ورودی شما بارگذار خودکار کامپوزر را یک بار فراخوانی می‌کند:

<?php
require __DIR__.'/vendor/autoload.php';

بارگذار خودکار فضای‌نام RtlyKit\ را به پوشهٔ src/ بسته نگاشت می‌کند و یک فایل کمکی را هم بارگذاری می‌کند که توابع کمکی فضای‌نام‌دار (RtlyKit\jdate() و بقیه) را تعریف می‌کند. آن فایل هیچ تابع سراسری تعریف نمی‌کند؛ نام‌های کوتاهِ اختیاری در توابع کمکی و سراسری‌ها آمده است.

بسته‌های اختیاری#

composer require nesbot/carbon          # ماکروهای Carbon: toJalali()، createFromJalali()، ...
composer require illuminate/support     # فقط در پروژه‌های غیرلاراولی که قطعه‌های لاراولی را می‌خواهند

هر دو یکپارچگی خودکار فعال می‌شوند. ماکروهای Carbon وقتی ثبت می‌شوند که بارگذار خودکار Carbon را پیدا کند. در برنامهٔ لاراول، ارائه‌دهندهٔ سرویس و نام مستعار فاساد Jalali با کشف خودکار بسته پیدا می‌شوند و چیزی به config/app.php اضافه نمی‌شود. اگر استقرار شما کشف را کش می‌کند، پس از نصب در پروژهٔ لاراولیِ موجود php artisan package:discover را اجرا کنید.

نصب بدون PHP روی دستگاه (داکر)#

اگر PHP و کامپوزر محلی ندارید، از ایمیج‌های رسمی اجرایشان کنید. از پوشهٔ پروژه:

docker run --rm -v "$PWD":/app -w /app composer:2 require enaxon/rtly-kit
docker run --rm -v "$PWD":/app -w /app php:8.3-cli php quick.php

فرمان اول بسته را در vendor/ نصب می‌کند؛ دومی اسکریپتی مثل اسکریپت شروع سریع را با PHP 8.3 اجرا می‌کند (ایمیج رسمی CLI شامل mbstring است). برای کار روی خود کتابخانه، مخزن را کلون کنید و از docker-compose.yml آن استفاده کنید:

docker compose -f tools/docker-compose.yml run --rm php composer install
docker compose -f tools/docker-compose.yml run --rm php composer test
docker compose -f tools/docker-compose.yml run --rm php php -r 'require "vendor/autoload.php"; echo RtlyKit\jdate("2026-03-21")->format("Y/m/d");'

نسخه‌های پشتیبانی‌شده#

  • PHP نسخه‌های 8.2، 8.3 و 8.4 (ماتریس CI). انتظار می‌رود نسخه‌های جدیدتر 8.x هم کار کنند ولی هنوز در ماتریس نیستند.
  • لاراول 11 و 12.
  • Carbon نسخهٔ 3.
  • نسخه‌گذاری. پیش از 1.0.0 هر انتشار فرعی ممکن است تغییر ناسازگار داشته باشد. هر مورد با مراحل مهاجرت در راهنمای ارتقا فهرست شده است (ارتقا) و تعهد سازگاری و فهرست کلاس‌های داخلی در پایداری API آمده است. تا 1.0.0 نسخهٔ فرعی را در قید composer.json ثابت کنید (قید تیلدا مثل ~0.x.y با نسخه‌ای که آزموده‌اید) و پیش از بالا بردن آن راهنمای ارتقا را بخوانید.

راستی‌آزمایی نصب#

فایل verify.php را در ریشهٔ پروژه بسازید:

<?php
require __DIR__.'/vendor/autoload.php';

echo PHP_VERSION, "\n";
echo extension_loaded('mbstring') ? "mbstring: yes\n" : "mbstring: NO\n";
echo \RtlyKit\jdate('2026-03-21')->format('Y/m/d'), "\n";   // 1405/01/01

با php verify.php اجرا کنید. خط آخر باید 1405/01/01 چاپ کند؛ نسخهٔ PHP زیر 8.2 یا mbstring: NO یعنی محیط پیش‌نیازها را ندارد. دو فرمان کامپوزر هم کمک می‌کنند:

composer show enaxon/rtly-kit            # نسخهٔ نصب‌شده و فراداده
composer check-platform-reqs          # PHP و افزونه‌ها را در برابر همهٔ بسته‌های نصب‌شده می‌سنجد

اگر چیزی کار نکرد#

  • Class "RtlyKit\..." not found یا Call to undefined function RtlyKit\jdate(): vendor/autoload.php فراخوانی نشده یا بارگذار خودکار کامپوزر کهنه است؛ composer dump-autoload را اجرا کنید.
  • Call to undefined function jdate() (بدون فضای‌نام): نام‌های کوتاه سراسری اختیاری‌اند. از use function RtlyKit\jdate; استفاده کنید یا \RtlyKit\Globals::register() را صدا بزنید.
  • کامپوزر نصب نمی‌کند و از نسخهٔ PHP یا ext-mbstring می‌گوید: PHP 8.2 یا جدیدتر نصب کنید یا mbstring را در php.ini فعال کنید.
  • موارد بیشتر: عیب‌یابی و پرسش‌های پرتکرار.

حذف#

  1. بسته را حذف کنید: composer remove enaxon/rtly-kit. این کار بارگذار خودکار را هم دوباره می‌سازد.
  2. استفاده‌های خودتان را پاک کنید: خط‌های use RtlyKit\... و use function RtlyKit\...، فراخوانی‌های \RtlyKit\Globals::register() و بلوک‌های catch برای RtlyKit\Exceptions\*. برای یافتن همه، کدتان را با RtlyKit جست‌وجو کنید.
  3. پروژه‌های Carbon: ماکروها (toJalali، jformat، toHijri، toHebrew، createFromJalali، createFromHijri، createFromHebrew) با بسته می‌روند؛ ابتدا فراخوانی‌هایشان را جایگزین کنید.
  4. پروژه‌های لاراول: قواعد اعتبارسنجی national_code، sheba، bank_card، iran_mobile، mobile، postal_code و vehicle_plate را از فرم‌ریکوئست‌ها، JalaliCast را از مدل‌ها، هر استفاده از فاساد Jalali و هر فایل ترجمه‌ای را که از بسته کپی کرده‌اید پاک کنید. سپس php artisan optimize:clear را اجرا کنید. دادهٔ ذخیره‌شده در پایگاه داده با حذف بسته دست‌نخورده می‌ماند؛ پیش از برداشتن کست بررسی کنید که کست چگونه آن را ذخیره کرده است.

بسته چیزی بیرون از vendor/ نصب نمی‌کند (جز قفل کامپوزر و فرادادهٔ بارگذار خودکار)، پس چیز دیگری برای پاک‌سازی نیست.
