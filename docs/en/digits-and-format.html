Digits#

RtlyKit\Number\Digits converts between the three digit sets used in Iranian software: English (0-9), Persian (۰-۹, U+06F0 to U+06F9) and Arabic-Indic (٠-٩, U+0660 to U+0669). The class is pure string replacement: it never throws, never touches other characters, and does not change decimal or thousands separators.

<?php
require 'vendor/autoload.php';

use RtlyKit\Number\Digits;

echo Digits::toPersian('Tel 0912 / 2024'), "\n";   // Tel ۰۹۱۲ / ۲۰۲۴
echo Digits::toPersian(1234.5), "\n";              // ۱۲۳۴.۵
echo Digits::toArabic(2026), "\n";                 // ٢٠٢٦
echo Digits::toEnglish('۱۲۳ ٤٥٦ abc'), "\n";        // 123 456 abc
echo Digits::arabicToPersian('٠١٢ 345'), "\n";      // ۰۱۲ 345
MethodInputWhat it does
toPersian($value)string, int, floatEnglish digits become Persian. Persian and Arabic-Indic digits that are already in a string are left as they are
toArabic($value)string, int, floatEnglish digits become Arabic-Indic
toEnglish($value)stringPersian and Arabic-Indic digits both become English
arabicToPersian($value)stringOnly Arabic-Indic digits become Persian; English digits stay

convert()#

convert() normalizes to English first and then renders the target set. The target name is case-insensitive: persian, fa and farsi give Persian digits; arabic and ar give Arabic-Indic digits; anything else, including a typo, gives English.

echo Digits::convert('۱۲۳', 'ar'), "\n";        // ١٢٣
echo Digits::convert('123', 'fa'), "\n";        // ۱۲۳
echo Digits::convert('٣٤٥', 'FARSI'), "\n";     // ۳۴۵
echo Digits::convert('۱۲۳', 'x'), "\n";         // 123
Numbers as input. toPersian() and toArabic() accept int and float and convert them with a plain (string) cast, so the decimal separator stays a Latin dot (۱۲۳۴.۵) and there are no thousands separators. For human-facing numbers use Format::withSeparator() below. The helpers to_persian_digits(), to_english_digits(), to_persian() and to_english() wrap these methods; see Helpers and globals.

The validators use Digits::toEnglish() for their normalization, so users may type in any digit set; see Normalization.

Number formatting#

Format::withSeparator() formats a number with thousands separators and Persian digits. By default it uses the Arabic thousands separator ٬ (U+066C) and decimal separator ٫ (U+066B), the characters Persian typography prescribes. It never rounds.

use RtlyKit\Number\Format;

echo Format::withSeparator(1234567), "\n";            // ۱٬۲۳۴٬۵۶۷
echo Format::withSeparator('1,234,567.5'), "\n";      // ۱٬۲۳۴٬۵۶۷٫۵
echo Format::withSeparator('۱٬۲۳۴٫۵'), "\n";          // ۱٬۲۳۴٫۵
echo Format::withSeparator('0001234'), "\n";          // ۱٬۲۳۴
echo Format::withSeparator('+12345'), "\n";           // ۱۲٬۳۴۵
echo Format::withSeparator(1.0), "\n";                // ۱

What it accepts#

  • An int, a finite float, or a numeric string with optional sign, digits in any of the three sets, and an optional fraction.
  • In strings, these are discarded as grouping marks: ,, ٬ (U+066C), regular spaces and the no-break space. The Arabic decimal separator ٫ (U+066B) is read as the decimal point. A plain . is the decimal point too.
  • Leading zeros of the integer part are dropped, a leading + is dropped, and a leading - is kept.

Anything that is not a plain decimal after this cleanup throws InvalidNumberException: 'abc', the empty string, scientific notation in a string ('1e5') and NaN or INF. The exception carries a stable error code (invalid_number, non_finite_number, input_too_long) that you can read with getErrorCode(); see Error handling.

Custom separators#

The second and third arguments replace the thousands and decimal separators. The digits are still converted to Persian:

echo Format::withSeparator(1234567, ','), "\n";            // ۱,۲۳۴,۵۶۷
echo Format::withSeparator(1234567.5, ',', '.'), "\n";     // ۱,۲۳۴,۵۶۷.۵

For English digits, convert the result back with Digits::toEnglish().

Floats and exactness#

A float is expanded to 15 decimal places and trailing zeros are trimmed, so binary representation noise can show up. If you need an exact decimal, pass a string:

echo Format::withSeparator(0.1 + 0.2), "\n";       // ۰٫۳
echo Format::withSeparator(-1234567.891), "\n";    // -۱٬۲۳۴٬۵۶۷٫۸۹۱۰۰۰۰۰۰۰۶۱۴۶۷
echo Format::withSeparator('-1234567.891'), "\n";  // -۱٬۲۳۴٬۵۶۷٫۸۹۱
Money and large values. Keep amounts as strings or integers (rials) end to end. Floats cannot represent most decimals exactly, and the formatter reproduces whatever digits the float actually holds.

Exactly 1000 digits are formatted normally. All the caps in one table are in Limits. The helper format_number() calls Format::withSeparator() with the defaults.

Ordinals#

Format::ordinal() returns the Persian ordinal word for a non-negative integer. It builds the cardinal words with NumberToWords (see Number to words) and then applies the suffix rules:

  • 1 is the irregular «اول».
  • A cardinal ending in «سه» becomes «سوم»; this also covers 23, 33 and so on.
  • A cardinal ending in «ی» (as in «سی») takes a half-space and «ام».
  • Everything else just adds «م».
echo Format::ordinal(1), "\n";     // اول
echo Format::ordinal(2), "\n";     // دوم
echo Format::ordinal(3), "\n";     // سوم
echo Format::ordinal(21), "\n";    // بیست و یکم
echo Format::ordinal(23), "\n";    // بیست و سوم
echo Format::ordinal(30), "\n";    // سی‌ام
echo Format::ordinal(33), "\n";    // سی و سوم
echo Format::ordinal(100), "\n";   // صدم
echo Format::ordinal(1000), "\n";  // یک هزارم
echo Format::ordinal(0), "\n";     // صفرم
echo Format::ordinal(3.0), "\n";   // سوم

Integral floats like 3.0 are accepted. Negative numbers, fractions (2.5) and non-finite floats throw InvalidNumberException (invalid_number, or non_finite_number for INF and NaN). The helper is ordinal().

Words, not digits. ordinal() returns the spelled-out word. It does not produce short numeric forms; build those yourself with Digits::toPersian() if you need them.
