What the class does#

RtlyKit\Calendar\Jalali is an immutable date-time value in the Persian (Solar Hijri) calendar. Internally it wraps one DateTimeImmutable instant, so it has a time zone, a Unix timestamp and an exact Gregorian counterpart; the Jalali year, month and day are computed from that instant. Every modifier returns a new object and the original never changes. The class is final and implements the shared CalendarDate contract described in Convert and compare dates.

Prerequisites. Install the package (Installation). All examples assume this header:

<?php
require 'vendor/autoload.php';

use RtlyKit\Calendar\Jalali;
use RtlyKit\Exceptions\InvalidDateException;
use function RtlyKit\jdate;   // namespaced helper, same as Jalali::make()
Known limitation. The conversion implements the arithmetic 33-year-cycle rule (leap years at residues 1, 5, 9, 13, 17, 22, 26, 30 modulo 33). It is not the astronomical calendar used for the official Iranian calendar. For the modern years it agrees with the official calendar, but the two rules are different by construction and may disagree on a leap day in some far past or future year. Do not use this class as an authority for legal deadlines that depend on the official publication.

Creating dates#

From components: create()#

create($year, $month, $day, $hour = 0, $minute = 0, $second = 0, $timezone = null) builds a date from Jalali components. The date is validated against the real month length of that year, so 1404/12/30 (1404 is not a leap year) is rejected while 1403/12/30 is accepted. Without a time zone the PHP default time zone (date_default_timezone_get()) is used.

$tehran = new DateTimeZone('Asia/Tehran');
$d = Jalali::create(1404, 7, 15, 14, 30, 5, $tehran);

echo $d;                                   // 1404/07/15 14:30:05
echo $d->getTimestamp();                   // 1759834805
echo $d->toGregorian()->format('c');       // 2025-10-07T14:30:05+03:30

From anything: make()#

Jalali::make($time = null, $timezone = null) accepts a DateTimeInterface, another CalendarDate (Hijri, Hebrew, Jalali), an int Unix timestamp, a string or null (now). The namespaced helper jdate() is a thin alias of it.

$utc = new DateTimeZone('UTC');

echo Jalali::make(new DateTimeImmutable('2026-03-21 12:00', $utc)); // 1405/01/01 12:00:00
echo Jalali::make(0, $utc);                                        // 1348/10/11 00:00:00
echo jdate('2026-03-21')->format('l j F Y');                       // شنبه 1 فروردین 1405
echo Jalali::now();      // current instant in the default time zone
echo Jalali::today();    // today at 00:00:00

String semantics of make()#

Strings are handled in this order:

  1. Persian and Arabic digits are converted to English digits, and the string is trimmed. An empty or whitespace-only string throws InvalidDateException.
  2. If the string looks like Y/m/d or Y-m-d with a 3 or 4 digit year, optionally followed by H:i or H:i:s (separated by a space or T), and the year is below 1700, it is read as a Jalali date.
  3. Every other string, including any year of 1700 or later, is passed to DateTimeImmutable and read as Gregorian or free-form text ('2025-10-07', 'tomorrow', '10 October 2025').
echo Jalali::make('1403/12/30');          // 1403/12/30 00:00:00
echo Jalali::make('۱۴۰۴/۰۷/۱۵');          // 1404/07/15 00:00:00   (Persian digits)
echo Jalali::make('1404-07-15 08:05');    // 1404/07/15 08:05:00
echo Jalali::make('2025-10-07')->format('Y/m/d');  // 1404/07/15   (Gregorian text)
echo Jalali::make('1700/01/01')->format('Y/m/d');  // 1078/10/12   (1700 or later is Gregorian)
Watch the 1700 boundary. A string such as '0001-01-01' or '1500-06-01' is read as a Jalali date, not as a Gregorian one. To pass a real Gregorian date earlier than year 1700, build a DateTimeImmutable yourself and hand that object to make().

Invalid input always raises InvalidDateException:

foreach (['1404/12/30', '1404/13/01', '1404/07/15 25:00', '', 'garbage'] as $s) {
    try {
        Jalali::make($s);
    } catch (InvalidDateException $e) {
        echo "'$s': ", $e->getMessage(), "\n";
    }
}
// '1404/12/30': Invalid Jalali date: 1404/12/30
// '1404/13/01': Invalid Jalali date: 1404/13/1
// '1404/07/15 25:00': Invalid time: 25:0:0
// '': Unable to parse an empty date string.
// 'garbage': Unable to parse date: garbage

With a format: createFromFormat()#

Jalali::createFromFormat($format, $time, $timezone = null) parses with the PHP DateTime::createFromFormat token syntax (digits may be Persian) but interprets the year, month and day as Jalali values. Gregorian-only limits such as "February has at most 29 days" do not apply; the Jalali calendar validates the result.

echo Jalali::createFromFormat('Y/m/d H:i', '1404/07/15 08:30', $tehran); // 1404/07/15 08:30:00
echo Jalali::createFromFormat('d-m-Y', '31-06-1404');                    // 1404/06/31 00:00:00

try {
    Jalali::createFromFormat('Y/m/d', 'abc');
} catch (InvalidDateException $e) {
    echo $e->getMessage();   // Unable to parse 'abc' with format 'Y/m/d'
}

Supported range and errors#

Supported Jalali years are Jalali::MIN_YEAR = -620 to Jalali::MAX_YEAR = 9377. This is exactly the span that maps to Gregorian years 1 to 9999: the first supported day is -620/01/01 (0001-03-21) and the last is 9377/12/30 (9999-03-20). Every entry point checks the range and throws only InvalidDateException (never a TypeError, ValueError or DateMalformed* exception), including create(), make(), createFromFormat(), integer timestamps, add*()/sub*() and the static converters.

foreach ([[-621, 1, 1], [9378, 1, 1], [1404, 12, 30], [1404, 0, 1], [1404, 7, 31]] as [$y, $m, $d]) {
    try {
        Jalali::create($y, $m, $d);
    } catch (InvalidDateException $e) {
        echo $e->getMessage(), "\n";
    }
}
// Invalid Jalali date: -621/1/1
// Invalid Jalali date: 9378/1/1
// Invalid Jalali date: 1404/12/30
// Invalid Jalali date: 1404/0/1
// Invalid Jalali date: 1404/7/31

Time components are checked too: Jalali::create(1404, 1, 1, 24, 0, 0) throws Invalid time: 24:0:0. An integer timestamp outside Gregorian years 1 to 9999 throws Timestamp out of the supported range: ....

Catch InvalidDateException to handle only calendar problems, or the base class RtlyKit\Exceptions\RtlyKitException (also the marker interface RtlyKitThrowable) to handle every error of the library. See Error handling.

Weekday numbering#

Jalali weeks start on Saturday: getDayOfWeek() and the w format token return 0 for Saturday and 6 for Friday; the N token is 1 (Saturday) to 7 (Friday). Hijri and Hebrew are different: they are Sunday-first (0 = Sunday), like PHP's own w. Never share weekday numbers across calendars; compare instants instead.

$d = Jalali::create(1404, 7, 15);           // a Tuesday
foreach (range(0, 6) as $i) {
    $x = $d->addDays($i);
    echo $x->getDayOfWeek(), ':', $x->format('l'), ' ';
}
// 3:سه‌شنبه 4:چهارشنبه 5:پنجشنبه 6:جمعه 0:شنبه 1:یکشنبه 2:دوشنبه

Formatting#

format($pattern = 'Y/m/d H:i:s', $persianDigits = false) evaluates PHP date()-style tokens in the Jalali calendar. Pass true as the second argument to convert all digits to Persian. A backslash escapes the next character. Characters that are not tokens are copied unchanged. A pattern longer than Jalali::MAX_FORMAT_LENGTH (256 bytes) throws InvalidDateException.

$d = Jalali::create(1404, 7, 15, 14, 30, 5, $tehran);

echo $d->format('l j F Y');            // سه‌شنبه 15 مهر 1404
echo $d->format('Y/m/d', true);        // ۱۴۰۴/۰۷/۱۵
echo $d->format('c');                  // 1404-07-15T14:30:05+03:30
echo $d->format('h:i A');              // 02:30 بعد از ظهر
echo $d->format('g:i a');              // 2:30 ب.ظ
echo $d->format('\Y: Y, \d: d');       // Y: 1404, d: 15
echo $d->format('t L z W N D');        // 30 0 200 41 4 س
TokenMeaning

m nMonth with and without leading zero

d jDay with and without leading zero

Shifting and snapping#

Every modifier returns a new instance; the time zone is preserved.

MethodBehaviour
addDays() subDays()Whole days on the underlying instant
addHours() addMinutes() addSeconds() and the sub* formsExact elapsed time
addMonths() subMonths()Calendar months; the day is clamped to the target month's length
addYears() subYears()Same as 12 months per year; 30 Esfand in a leap year becomes 29 Esfand in a regular year
startOfDay() endOfDay()00:00:00 and 23:59:59 of the same day
startOfMonth() endOfMonth()First day 00:00:00; last day 23:59:59
startOfYear() endOfYear()1 Farvardin 00:00:00; last day of Esfand 23:59:59
 
$x = Jalali::create(1403, 12, 30);              // last day of a leap year
echo $x->addDays(1);                            // 1404/01/01 00:00:00
echo $x->subDays(30);                           // 1403/11/30 00:00:00
echo $x->addHours(30);                          // 1404/01/01 06:00:00
echo $x->addYears(1);                           // 1404/12/29 00:00:00  (clamped)
echo $x->subMonths(13);                         // 1402/11/30 00:00:00
echo Jalali::create(1404, 6, 31)->addMonths(1); // 1404/07/30 00:00:00  (clamped)

$m = Jalali::create(1404, 7, 15, 14, 30, 5);
echo $m->startOfMonth();   // 1404/07/01 00:00:00
echo $m->endOfMonth();     // 1404/07/30 23:59:59
echo $m->startOfYear();    // 1404/01/01 00:00:00
echo $m->endOfYear();      // 1404/12/29 23:59:59

Moving past the supported range, or by an absurd amount, throws InvalidDateException instead of wrapping around:

try { Jalali::create(9377, 1, 1)->addYears(1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Jalali year out of the supported range: 9378

try { $x->addDays(PHP_INT_MAX); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Cannot shift a date by 9223372036854775807 days: out of the supported range.

Comparing and measuring#

Comparison methods (eq ne gt gte lt lte equals isBefore isAfter between isPast isFuture isToday) compare instants, and accept any CalendarDate or DateTimeInterface. So two values are equal only when they are the same moment, which depends on the time zone, not just the printed date.

$a = Jalali::create(1405, 1, 1, 0, 0, 0, $tehran);
var_dump($a->eq(new DateTimeImmutable('2026-03-21 00:00', $tehran))); // bool(true)
var_dump($a->between(Jalali::create(1404, 1, 1), Jalali::create(1406, 1, 1))); // bool(true)
MethodSemantics
diffInDays($other, $absolute = true)Whole days, truncated toward zero. With false the sign is that of $this - $other
diffInMonths($other, $absolute = true)Whole Jalali months; the day and time of day count (15 Farvardin to 14 Tir is 2 months)
diffInYears($other, $absolute = true)Whole Jalali years, anniversary based
 
$jan = Jalali::create(1404, 1, 1);
$feb = Jalali::create(1404, 2, 1);
echo $jan->diffInDays($feb);                 // 31
echo $jan->diffInDays($feb, false);          // -31
echo Jalali::create(1404, 1, 15)->diffInMonths(Jalali::create(1404, 4, 14)); // 2
echo Jalali::create(1380, 5, 5)->diffInYears(Jalali::create(1404, 5, 4));    // 23
echo Jalali::create(1380, 5, 5)->diffInYears(Jalali::create(1404, 5, 5));    // 24

echo implode(',', array_filter(range(1399, 1410), Jalali::isLeapYear(...))); // 1399,1403,1408

try { Jalali::gregorianToJalali(10000, 1, 1); }
catch (InvalidDateException $e) { echo $e->getMessage(); }
// Gregorian date out of the supported range (years 1-9999): 10000-1-1

Practical notes#

  • Time zones. Dates created without a zone use the PHP default zone. Pass a DateTimeZone to create()/make() whenever the result must not depend on server configuration. Hour, minute and the date itself are read in the instance's zone.
  • Day boundaries. The day changes at civil midnight in the instance's zone, as everywhere in this library.
  • Use as a value. Instances are Stringable, safe to share and to store in arrays; sort by getTimestamp().
  • Related. Convert to other calendars and compare across calendars in Convert and compare dates; add Carbon integration in Carbon macros; check Iranian holidays in Holidays.
